# アクティブ難易度（脅威度とアクト制）

[経済とバランス](./09-経済とバランス.md)・[選択型イベント設計](./16-選択型イベント設計.md)・[期間修正イベント設計](./17-期間修正イベント設計.md)・[経済再編とプレイ感改善](./19-経済再編とプレイ感改善.md) を踏まえ、静的な難易度（固定減衰 + 閾値付きイベント抽選）を**状況に応答するアクティブな難易度**へ再設計する計画。数値はすべて仮置きで、sim で確定する。

**状態: 実装済み（2026-08-05、D1–D4 完了。D5 は任意残）** — 確定値と sim 結果は §8 を参照。

## 0. 背景と動機

- 現行の難易度は静的: 減衰は固定（power -10 / medical -8 / food -5 / morale -2）、イベントは資源閾値で条件付きの固定 weight 抽選。プレイヤーへの能動的な押し返しがない。
- v1.3 の教訓（docs/19）: random と skilled は食料で強く相関し、汎用レバーは両方を同方向に動かす。foodPerUnit（人員比例）だけがデカップリングレバーだった。
- full_recovery 到達性調査（docs/19 §7）の知見: 好調なランは「余裕状態」（食料バッファ・高電力/医療）に滞留する。**高閾値への課税は、低閾値への救済（E4 で失敗）と異なり、無作為ランがほとんど到達しない** → 第二のデカップリングレバーになりうる。

### 目標（ユーザー確認済み）

1. **デカップリングに挑戦**: 無作為の底上げ（目標 5–10%）と熟練の適正化を同時に狙う。数値は結果を見て判断。熟練の極端な高騰は不可
2. **レッドライン: お任せ配置（autoAssign）でクリアが定常化しない**。熟練生存率 60% 超は再調整/巻き戻し
3. **体験として不快にしない**: 予告・備え・応答の可能性を伴う圧にする（§2.3）
4. **full_recovery は到達可を維持**: `tests/full-recovery.test.ts`（現行 37/60）を番人として使う。閾値 `>=10` は維持し、達成不能なら設計失敗として検出
5. **アクト3 の収入減（income ×0.9）は採用**（ユーザー確認済み）
6. **破壊的変更は許容**（旧セーブは従来どおり破棄→新規ゲーム）。ただし本計画は GameState の型変更を伴わないため `SAVE_VERSION` 据え置きで実現できる見込み

## 1. 方針

### 設計原則

1. **B が公平性の背骨、A が応答層**: アクト制（B）は予定されたエスカレーション（予測可能・計画可能）、派生脅威度（A）は余裕への緩やかな課税（背景で静かに効く）
2. **イベント総数は増やさない**: 1日1件の自動イベント抽選（events.ts）の**重み構成**だけを動かす。ペース不変、決定論維持
3. **純粋・決定的を保つ**: threatLevel は既存 GameState からの派生関数。新規の永続 state なし（SAVE_VERSION=5 据え置き）
4. **数値は balance.ts**: `BALANCE.threat` / `BALANCE.acts` を新設。ロジックにマジックナンバー禁止
5. **ベース weight は不変**: 既存イベントの weight 関数自体は触らず、threat トーンに**乗算スケーリング**のみ適用（v1.3「イベント weight 再調整禁止」の精神を維持）
6. **ゲート制**: D1–D4 各マイルストーン末にゲート確認。1マイルストーン = 1コミット（CI緑条件）

### 非目標

- 道路復旧の coef 変更（docs/19 同様のナイフエッジ）
- 探索の経済（cost・帰還率・報酬）の変更
- 新規イベントの追加（D5 の任意拡張まで見送り。コアは既存イベントの構成変化のみで実現）
- 選択イベント（trade_offer / power_crisis / stockpile_crisis / expedition）の weight スケーリング（v1 では自動イベントのみ）
- うねり（脅威バジェットの蓄積・消化）の永続 state 実装（v2 候補。§6 参照）

## 2. 設計

### 2.1 B: アクト制（予定されたエスカレーション）

30日を3幕に分け、境界で期間修正（Modifier）を適用する。

| アクト | 日数 | 名称（仮） | 修正 |
| --- | --- | --- | --- |
| act1 | 1–10 | 救援期 | なし（基準） |
| act2 | 11–20 | 膠着期 | `decay:power ×1.25` |
| act3 | 21–30 | 正念場 | `decay:power ×1.5` / `decay:medical ×1.25` / `income:budget ×0.9` |

- **実装**: `finalizeDay`（engine.ts）で、現在日が属するアクトの Modifier が無ければ**冪等に追加**（`addModifier` の id 重複排除を利用）。境界跨ぎの検出漏れ（旧セーブの途中再開等）を防ぐため、境界イベント方式ではなく毎日の存在保証方式にする。追加が起きた日のみ遷移 effect を1本発行（「設備の劣化が目立ち始めた」等の flow ビート）→ playback / StatusWall バッジに機構無変更で反映
- **daysLeft**: アクト残り日数。`tickModifiers` で自然消滅
- act3 の収入減: income 45→41（電力ボーナス時）/ 30→27。終盤の予算競争（repair 20 + medical 15 + soup 15 = 50）を意図的に締める
- **予測可能性**: 境界 effect で次の幕を告知。プレイヤーは「21日から正念場」を学習・計画できる（フェアなアクティブさ）

### 2.2 A: 派生脅威度（状況応答層）

`threatLevel(state)` を既存 state からの純粋関数として新設（`src/game/threat.ts`）。`determineDayEvents`（events.ts）で **threat トーンの自動イベント**の実効重みをスケーリングする。

```
threatLevel = actBase[act] + slackCount
実効weight = weight × min(1 + scale × threatLevel, cap)   （threat トーンのみ）
```

**slackCount（余裕の計測、各条件で +1、最大5）**:

| 条件 | 仮閾値 | 根拠 |
| --- | --- | --- |
| 食料 ≧ N日分の消費 | 4日分（`present × foodPerUnit`） | E4 の教訓を逆用。無作為が到達しにくい高閾値 |
| power ≥ 70 | 70 | full_recovery の目標値帯 |
| medical ≥ 70 | 70 | 同上 |
| morale ≥ 65 | 65 | calm / volunteers の安定帯 |
| stockpile ≥ 40 | 40 | 備蓄の溜め込み検出 |

**actBase**: act1 = 0 / act2 = 1 / act3 = 2（日数経過そのものの脅威上昇。B と合流する項）

**tone の分類**: `EventDef` に `tone?: 'threat' | 'boon'` を追加（**定義側の型のみ。GameState / セーブ無影響**）。自動イベント42件を分類し、threat のみスケーリング。boon は不変（逆転の芽を潰さない）。分類が曖昧な arrival（人員増加 = 食料負担 + 士気+2）は tone なし = 非スケーリング。

- threat（約20件）: generator_failure / road_collapse / infection / protest / water_shortage / theft / elder_death / wildlife / landslide_warning / landslide_actual / food_spoilage / cold_snap / rumor / rat_infestation / insomnia / aftershock / second_wave / storage_flood / generator_overheat / typhoon
- boon（約21件）: hidden_stockpile / foraging / power_restored / medical_donation / volunteers / rescue_contact / clear_weather / manna / supply_drop / hot_spring / miracle_harvest / sunny_stretch / animal_trap / traveling_engineer / volunteer_surge / clean_water / cached_fuel / radio_repair / childbirth / gratitude 等

**デカップリングの仕組み**: slack 課税は好調ラン（≈熟練）に主に効く → 熟練が下がる → そこで v1.3 の静的食料圧（`foodPerUnit` / `food.decay`）を緩めて無作為を底上げし、熟練は slack 課税 + アクト圧で天井を戻す（D4 で反復）。

### 2.3 不快にしないための設計規則（体験面）

1. **予告**: アクト境界は effect で告知。脅威は「ある日突然の理不尽」ではなく「来るものと分かっている圧」にする
2. **上限**: スケーリング倍率に cap（仮 ×2.0）。脅威の壁を作らない。scale も緩やか（仮 0.2/レベル）
3. **備蓄を直接奪わない**: slack 課税は既存イベントの**頻度**を動かすのみ。バッファを直接没収する新効果は追加しない。既存の theft / food_spoilage 等は小規模・条件付きのまま
4. **バッファは依然として正の期待値**: slack 状態のランは非 slack ランより生存率が高いことを sim で確認する（不変条件。逆転していたら課税が強すぎて設計失敗）
5. **総イベント数不変**: threat 頻度の上昇は boon 頻度の相対低下として現れるが、1日1件のペース自体は変わらない
6. **Fiction（言い分）**: アクト圧は「季節の悪化・設備の老朽化」、slack 圧は「町が立ち直るほど、問題も大きく集まる」として effect 文言に反映する

### 2.4 full_recovery への影響（番人）

- act3 の decay 増（power -15/日）は終盤スプリント（docs/19 §7 の狙うプレイ）と正面から衝突し、FR 率は下がると予想される。**これは設計意図**（着地を contested にする）だが、`tests/full-recovery.test.ts` の `>=10` で「到達不能に戻らない」ことを保証する
- FR 率が極端に下がった場合はアクト倍率が行き過ぎのシグナルとして扱う

## 5. セーブ互換性

- **`SAVE_VERSION=5` 据え置き**（GameState の型変更なし。EventDef.tone は定義側のみ、アクト Modifier は既存 Modifier 型のインスタンス）
- 旧セーブの途中再開は finalizeDay の冪等保証で補完（初回 finalize でアクト Modifier が追加され、遷移 effect が1本流れる）
- 破壊的変更は許容済み（ユーザー確認）だが、本計画では不要の見込み。v2 のうねり機構で永続 state が必要になった場合のみ SAVE_VERSION 引き上げを検討

## 6. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| slack 課税が無作為の生存ランにも効く（E4 の二の舞） | デカップリング失敗 | D3 で「無作為ランの slack 到達率」を測定。高ければ閾値を引き上げ |
| アクト圧 + slack 課税で熟練が崩れすぎる | 狙ったプレイでも勝てない | D3 で FR 番人と熟練率を確認。scale / アクト倍率を下げる |
| 食料圧緩和で熟練が跳ねる（v1.3 で確認済みの現象） | レッドライン超過 | slack 課税とアクト圧で天井を作るのが本計画の狙い。反復で着地させ、超えたら緩和幅を縮小 |
| 脅威構成が偏り「ずっと悪いことが起きる」体感 | 不快 | 不変条件4（slack ≥ 非 slack の生存率）と threat 発火率の上限を目視。cap ×2.0 は動かしすぎない |
| RNG ストリーム変動で全イベント分布が動く | 意図しないドリフト | 決定論は保たれるため再現可。前後比較を必ず記録（規律） |
| FR 番人が割れる（<10） | 到達性の喪失 | アクト倍率が行き過ぎのシグナル。緩めて再測定 |

### v2 候補（本計画の範囲外）

- **threat スケーリングの選択イベントへの拡張** / **新規脅威イベントの追加**（D5 以降）

## 8. 実装記録（2026-08-05）

### 確定値（balance.ts）

```

threat: { scale: 0.2, cap: 2.0, actBase: [0, 1, 2],
  slack: { foodDays: 6, powerAt: 75, medicalAt: 75, moraleAt: 75, stockpileAt: 55 } }
```

tone 分類は自動イベント43件中 threat 22 / boon 20 / arrival は対象外（§2.2 リストに無名だった elderly_illness・ration_protest は効果の向きから threat に分類。実ファイルは43件で、docs 中の「42件」は数え誤差）。

### 計画からの逸脱とその理由

1. **アクト倍率の緩和**（計画中: act2 1.25 / act3 power 1.5・medical 1.25 → 確定: 1.1 / 1.25・1.15）: 計画仮数値のままでは FR 番人が 5–6/60 に割れた（§2.4 の「行き過ぎシグナル」どおり）。D2 コミット時点で CI 緑が必須のため、D2 内で緩和した
2. **slack 閾値の引き上げ**（計画中: 食料4日分/70/70/65/40 → 確定: 6日分/75/75/75/55）: 計画仮数値では初期状態が即 slack 2 になり、無作為ランの序盤まで課税した。閾値を引き上げて「真に余裕がある状態のみ課税」に変更
3. **無作為 5–10% は未達**: §「デカップリングの仕組み」の前提（slack 課税は好調ランにのみ効く）が観測と食い違った。下記

### D4 反復で得た知見（次回のバランス調整にも効く）

- **fpu/decay の緩和は熟練を大きく引き上げる**（v1.3 知見の再確認）。decay 2/fpu 4 で無作為は 4/120 まで上がるが熟練が 87% に爆発しレッドライン違反
- **ゲート方式は逆効果**: 「食料バッファ ≥2日のあるランだけ課税」を試したが、autoAssign は食料ギリギリで戦うため熟練が免税され 75% に上昇。無作為も守られなかった
- **アクト倍率の強化は熟練より FR を先に壊す**: autoAssign は任務の分散と犠牲の回転で減衰に耐えるが、FR は power/medical ≥70 の絶対値が要る。acts (1.35/1.6/1.4) で熟練 78→70% の間に FR は 28→9
- **slack のゲージ条件は選別度が低い**: 士気・医療・電力は boon イベントで崩壊直前のランも回復するため、無作為ランも slack 日数の約半分に到達する。食料・備蓄条件だけが選別的だが、両者とも終盤は枯れるため到達率が低い
- **無作為の生存は配置由来の食料収入で決まる**: 無作為配置の食料収入は約4/日（消費約23–25/日に対し）。イベント weight・探索経済・道路 coef は「触らないもの」のため、許容レバー内では 5% に構造的に届かない。v1.3 の「3%」も40ゲームの標本誤差で、400ゲーム測定の真値は v1.3 = 3/400・v1.4 = 1/400（同水準）
- **sim の種子噪声**: 60ゲームの熟練率は ±6pt 程度ぶれる。近い設定間の比較は 400ゲーム測定でもしない限り分解能不足
