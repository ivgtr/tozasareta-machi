# ユニット実装計画

[12-ユニット設計](./12-ユニット設計.md) に基づき、作業員モデル → ユニークユニットへの置換を実装する計画。v1（P1–P9、`985d0be`）は完成済みで、これは**既存の動くゲームの作り替え**である。アーキテクチャは維持し、データとロジックの内容を差し替える。

---

## 0. 進め方の原則

- **ヘッドレスファースト**: 元と同じく、コアを先に完成させ simulation でヘッドレス検証する。`U1=コア / U2=UI / U3=バランス`。
- **ゲート制**: 各マイルストーン末にゲートを確認しコミット（1マイルストーン = 1コミット）。
- **アーキテクチャ維持**: 純粋 reducer・データ駆動・アートスロット・simulation harness はそのまま再利用。
- **テストはフェーズごとに更新**: コアのテストは U1、UI のテストは U2 で書き換え、壊れたテストを放置しない。
- **セーブ非互換**: `SAVE_VERSION` を引き上げ、旧セーブは破棄（parse 失敗 → 新規ゲーム）。マイグレーションは設計しない（リリース前のため）。

| # | マイルストーン | 目的 | 主な成果物 | ゲート | サイズ | 依存 |

## 2. U1 詳細手順（コア）

1. `types.ts`: `Unit` / `Aptitude` / `TraitId` / `Condition` / `Placement`。`GameState.units`（`workers`・`characters` を削除）。`DayPlan.placements`。
2. `balance.ts` + `traits.ts`（新）: 適性係数・食料 perUnit・成長閾値・負傷/離脱確率・上限。特性メタデータ（id/名称/説明文/効果種別）。
3. `data/units.ts`（新）: 初期4ユニット、名前プール、`makeRandomUnit(rng)`。
4. `state.ts`: `createInitialState` をユニット付きに。
5. `actions.ts`: `resolvePlacement`（適性駆動）+ `preview` + `autoAssign`（貪欲法）。
6. `settlement.ts`: 食料=`units×4`、飢餓ランダム死亡、離脱、負傷/回復、成長、特性の存在効果（人気者/問題児）。
7. `events-data.ts`: 避難者→ランダムユニット、ユニーク加入3種、上限判定。
8. `store.ts`: zod スキーマ更新 + `SAVE_VERSION=2`。
9. **コアテスト書き換え**: actions/settlement/events/engine/simulation。ユニット生成・決定性のテストを追加。

## 3. U2 詳細手順（UI）

1. `UnitCard` コンポーネント: 4適性を任務対応色（労=amber/技=cyan/医=green/魅=gold）で表示、特性アイコン、負傷マーク。
2. `UnitDetails` モーダル: 適性バー、特性の説明文、成長進捗。
3. `DecisionBoard` 刷新: ユニットロスター + 任務スロット（ドロップゾーン）+ 選択→配置 + ドラッグ + キーボード + おまかせ配置 + リセット + 確認ステップ。
4. `StatusWall`: 人員を削除（ユニットは中央面板へ）。
5. `PlayScreen`: `chars` 状態 → `placements` へ。
6. `ui.test.tsx` を更新。

---

## 4. U3 詳細手順（バランス+DoD）

1. simulation の `randomPlan` を**ランダム配置**に更新。
2. 勝率・ending 分布・ユニット生存数を見ながら、適性係数・食料 perUnit・入手頻度を調整。
3. DoD（v1.1、§6）を再確認。

## 5. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 結合の強い refactor で既存ゲームが壊れる | 高 | フェーズごとのゲート + テストをフェーズごとに更新 |
| U1 後に旧UIがコンパイル不能 | 中 | U2 を直続。視覚確認は U2 後 |
| 適性駆動でバランス崩壊 | 中 | simulation harness + U3 で段階調整 |
| セーブ非互換 | 低 | バージョン引き上げ + 旧セーブの安全な破棄 |
| 操作の肥大（ドラッグ+おまかせ+モーダル） | 中 | クリック中核を先に、ドラッグ/おまかせは補助として段階実装 |
