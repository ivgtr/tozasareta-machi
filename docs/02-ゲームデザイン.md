# ゲームデザイン

## 管理資源

最初は次の4つだけでよい。

| 資源 | 意味 |
| --- | --- |
| 食料 | 住民の生存に直結 |
| 電力 | インフラ・医療・復旧作業を支える |
| 医療 | 住民の健康と死者数に関わる |
| 住民の士気 | 協力・反発・自主行動の発生に影響 |

## プレイヤーが動かせるもの

- 作業員
- 予算
- 備蓄品

## ターンの流れ

1日（1ターン）ごとに、複数の問題から対応先を選ぶ。すべてには対応できない。

### 選択肢の例

- 発電設備の修理に作業員を送る
- 道路を復旧して食料を確保する
- 医療班を増員する
- 住民向けの炊き出しを行う

発電所を優先すれば医療が不足し、食料確保を優先すれば復旧が遅れる、といった**交換条件**がゲームの中心となる。

## イベント

単なるランダムイベントではなく、過去の判断によって発生確率が変わるとシミュレーションらしくなる。

### イベント例

- 高齢者の体調不良が増える
- 発電機が故障する
- 隣町から避難者が来る
- 商店が隠していた備蓄が見つかる
- 豪雨で復旧中の道路が再び崩れる
- 住民が自主的に作業を手伝い始める
- 一部の住民が物資配分に反発する
- 救援隊から「あと5日で到着」と連絡が来る

### 発生確率が状態に依存する例

- 士気が低い状態が続けば抗議が発生する
- 医療を放置すれば感染症イベントが起こりやすくなる

## エンディング

単純な成功・失敗だけでなく、プレイヤーの方針を反映させる。同じ「クリア」でも結果が異なれば、別の方針を試す理由ができる。

| エンディング | 内容 |
| --- | --- |
| 完全復旧 | 多数の住民を守り、インフラも復旧させた |
| 管理された犠牲 | 町は存続したが、弱い立場の住民に大きな被害が出た |
| 住民自治 | 復旧は遅れたものの、住民同士が協力する仕組みが生まれた |
