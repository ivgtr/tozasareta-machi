## 1. ファイル所有権と衝突回避

衝突回避の基本は**ディレクトリ単位の所有権**。各フェーズは自分が所有するディレクトリしか触らない。例外は切替フェーズの P3 のみ（§2.3）。

| パス | 所有フェーズ | ルール |
| --- | --- | --- |
| `src/game/` | —（赤線） | **全フェーズで無変更**。型・step契約・決定性に触れない |
| `src/store/` | P1 が作成、P2 以降は凍結 | P2 以降の変更は独立コミット+テストを要する |
| `src/ui/` | P1 以降**凍結**、P3 で削除 | 凍結中は致命的バグのみ修正可。機能追加禁止（二重保守になる） |
| `src/scene/` | P1 が作成、P2–P6 の主戦場 | 新規コードはすべてここへ |
| `src/ui/assets/` | P1–P2 は Phaser が**読むだけ**。P3 で `src/assets/` へ移管 | 凍結中は追加・変更しない |
| `src/assets/` | P3 で作成（移管）。P4 以降 T2 の納品先 | — |
| エントリ（index.html / main） | **P3 のみ** | P1–P2 は dev 用入口（`?phaser` フラグ）で Phaser 骨格へ到達する |
| `tests/` | ゲームコア系は全期間無変更。UIスモークは P3 で削除→純TSテストに置換 | テストから Phaser を import しない（jsdom 非互換の回避） |
| `docs/00` | 各フェーズ終了時 | 完了記録・次のステップの更新 |

### 先に潰しておく衝突ポイント

1. **アセットディレクトリ**: P1–P2 は `src/ui/assets` を読み専用で使い、移管による React 版破壊を避ける。移管と React 削除は P3 の同じフェーズ内で完結させる
2. **store の二重管理**: P1 で純粋ロジックを `src/store/` に抽出し、`src/ui/store.ts` はそこへ委譲する薄い React バインドへ書き換える。移行期の正は `src/store/` の一つだけ
3. **エントリの共有**: 本番エントリは P3 まで触らない。Phaser 骨格は dev 入口から開く
4. **manifest の分裂**: `src/ui/art/manifest.ts` は P3 削除まで React 専用。Phaser 側は `src/scene/art/` にアートデータを新設する。移行期は両者の ART_SPECS 相当を**揃えておく**こと（P3 で統合）
5. **テストの import 境界**: Phaser を import するモジュールをテストが import しないよう、町ロジック（layout 導出・fx対応表・判定関数）は Phaser 非依存の純TSモジュールとして分離する

## 2. フェーズ別手順

### P0: 設計確定 — **完了**

docs/22（WB 全件確定）・docs/23・本ドキュメントが揃っている。Phase 0 の残り成果物（画面ラフ・UIキットのデザイントークン・layout データの実体）は P1/P2 の実装トラックで生成する。

### P1: Phaser 骨格 + store の純TS化

**入口条件**: docs/22–24 確定。`npm test` / `typecheck` / `lint` / `build` が緑。

**手順**:

1. コミットA「store の純TS化」
   - `src/store/` を新設: zod スキーマ（`SAVE_VERSION=5` 不変）/ save・load / history / settings / 中核ロジック。現 `src/ui/store.ts` は zod・reducer・save 系がすでに純粋なので、**移動+export 整形が主作業**（書き直しではない）。settings（`src/ui/settings.ts`）も同様に純粋コアを移し、`useSettings` は React バインドとして残す
   - `src/ui/store.ts`・`store-context.tsx` は `src/store/` へ委譲する薄いバインドへ書き換え
   - **`tests/store.test.ts` の import を `src/store/` へ更新**（テスト自体は維持）
   - 検証: 全テスト緑。React 版で save / undo / settings が従来どおり動く
2. コミットB「Phaser 骨格」
   - `npm i phaser`（**Phaser 3**。採用バージョンを docs/00 に記録）
   - `src/scene/`: Game 設定（**docs/22 §4.4**: Scale FIT + CENTER_BOTH・`pixelArt: true` / `roundPixels: true`・`type: AUTO`・レターボックス `#0a0e24`）/ Boot・Title・Play シーン骨格 / アセットローダー（`import.meta.glob` で `src/ui/assets` を読む URL マップ）
   - **デバイスクラス判定（wide ≥900px / narrow <900px）と設計サイズ切替（1280×720 / 480×854）の機構**（`scale.setGameSize` + リレイアウトのフック。docs/22 §4.4）
   - UIキット基礎: Panel / Button / Text / Gauge。見た目は docs/07 §2.2–2.4 のデザイントークンを踏襲
   - フォント: `index.html` が DotGothic16 / Press Start 2P を**すでに読み込んでいる**。新規リンクは追加せず、Phaser 側は `document.fonts.load` の完了を待ってから Text を描く
   - dev 入口（`?phaser` フラグ等）
   - 検証: typecheck / lint / build 緑。dev 入口で骨格が起動。**React 版に一切の変化がない**

**出口条件**: 両コミットが緑。docs/00 に P1 完了を記録。

**監督メモ**: シーンは React を import しない。store は `src/store/` から読む。このフェーズでゲームロジックをシーンに写し始めない（P2 の仕事）。座標系は docs/22 §4.5 の設計サイズ（論理px）を正とする。narrow の設計幅 480 は docs/23 の町ベース幅と一致させること（1倍以上の表示保証）。

### P2: Play シーンの等価構築（プレースホルダ）

**入口条件**: P1 完了。

**手順**（3コミット目安）:

1. コミットA: 町領域（グリッド+施設プレースホルダ、`src/scene/town/layout.ts`、`deriveFacilityView`）/ 人物トレイ / 配置モデル（DnD+タップ・preview・配置可否判定は `taskCost`/`sanitizePlan` 系を再利用）
2. コミットB: HUD / 計画ストリップ（autoAssign・commit・残表示）/ 詳細パネル / ログドロワー / メニュー。**wide / narrow の2レイアウト（docs/22 §4.5 の寸法どおり）+ resize/orientationchange 時のリレイアウト + セーフエリア回避**を含む
3. コミットC: playback 移植（`src/scene/playback/`、ビートモデル不変）/ 選択・加入帰還・エンディングのオーバーレイ / **等価性チェックリスト（付録A）の実行**
   - playback の移植対象は `buildBeats`（すでに純粋）・`UI_TIMING`・進行の状態機械。**`tests/playback.test.tsx` が `buildBeats` と `UI_TIMING` をカバーしているので、純粋部のカバレッジを `src/scene/playback/` を import する非 React テストとして引き継ぐ**（React フック部のテストは P3 で削除）

**出口条件**: 付録A が全項目通過。React 版が引き続き正常動作。docs/00 に記録。

**監督メモ**: 新規コードは `src/scene/` のみ。`src/ui/`・`src/store/` への変更禁止（致命的バグを除く）。決定性はゲームコアが保証しているので、Phaser 側に乱数やゲーム判定を持ち込まない。シーンの行き来（title↔play・canResume 判定）は現 `App.tsx` のロジックをそのまま移植する。**モバイル canvas には `touch-action: none` 相当を設定し、長押しコンテキストメニュー・ダブルタップズームを抑制する**（DnD の前提）。

### P3: 切替と React 撤去（原子フェーズ）

**入口条件**: P2 の等価性チェックリスト通過。

**手順**（1セッション。コミット分割は可だが直列・各コミット緑）:

1. エントリを Phaser へ切替（dev フラグ撤去）
2. 純TS層の Vitest を追加（town 導出・UIキット判定）
3. `src/ui/` を削除（コンポーネント・styles・store バインド）。テストは **`tests/ui.test.tsx` と `tests/playback.test.tsx` の React フック部を削除**（`tests/store.test.ts` は P1 で import 更新済み・維持。`tests/smoke.test.ts`・`portrait.test.ts` 等はゲームコア系なので無変更）
4. `src/ui/assets` → `src/assets` に移管し、ローダーの URL マップを更新
5. 検証: 全コマンド緑 + 手動チェックリスト（付録B）+ **セーブラウンドトリップ**（`SAVE_VERSION=5` の旧セーブが Phaser 版で読める）

**出口条件**: React 完全撤去。完了とバージョン相当の記録を docs/00 へ。

**監督メモ**: 共有パス（エントリ・assets・tests）に触れる唯一のフェーズ。**他セッションとの並行作業禁止**。失敗時はコミット単位で戻れるようにしておく。**main への push は GitHub Pages への自動デプロイ（deploy.yml）を発火する**ため、P3 のマージ=公開版が Phaser に切替わる。付録B を通過してからマージすること。

## 3. 共通規律

- 1フェーズ=1コミット（論理単位の分割は可）、CI緑を条件に（docs/11 §5）
- 検証コマンド: `npm test` / `npm run typecheck` / `npm run lint` / `npm run format:check`（落ちたら `npm run format`）/ `npm run build`。**CI は prettier の format:check を含む**ので省略しない。sim はゲームコア無変更のため原則不要（P6 のイベント画像優先度算出時のみ `npm run sim -- --reporter=verbose`）
- Phaser シーンはゲーム状態を持たない（表示キャッシュのみ）。入力は store 経由で `step`
- テストは Phaser を import しない
- コードにコメントは原則追加しない。数値は `balance.ts` 集約（UI定数は `src/scene/` 内の定数モジュールに集約し、マジックナンバー禁止の精神を維持）
- 韓国語・簡体字混入のチェック（docs/00 の規律。PNG は誤検出するのでテキストに絞る）

### A-2 主要操作経路

1. 計画 → 確定 → プレイバック（スキップ含む）→ 翌日

3. 探索送出 → 数日後帰還 → スポットライト → 翌日
4. undo → 再計画 → 確定
5. セーブ → リロード → 再開（日数・人員・modifier 一致。**choice フェーズ途中のセーブは、再開時に選択オーバーレイへ復帰する**）

8. 演出 OFF 設定 → playback が抑制され、結果が即時反映される（reducedMotion 経路の等価）
