## sim 測定のノウハウ（バランスを触るなら必読）

- sim の `console.log` は **`--reporter=verbose` が必要**: `npm run sim -- --reporter=verbose`
- 400ゲーム測定（真値の推定用）は `tests/simulation.test.ts` の `const GAMES = 40` を一時的に変更して `npx vitest run tests/simulation.test.ts --testNamePattern 無作為 --reporter=verbose`（コミット前に必ず 40 に戻す）
- **60ゲームの熟練率は ±6pt 程度の種子噪声**。近い設定間の比較は 400ゲームで測らないと分解能不足（v1.4 D4 で 30↔23% の「差」がノイズだった実例）
- 決定性: 同じ seed + 同じ行動 = 同じ結果。パラメータ変更はイベント抽選の RNG ストリーム自体をずらすため、前後比較は「別の宇宙」として読むこと
- レッドライン（今後の調整でも維持すること）: 熟練 ≤60%（autoAssign クリアの定常化禁止）/ FR 番人 `tests/full-recovery.test.ts` ≥10 / slack 不変条件（sim stats にアサーションあり）
- **触らないもの**: 道路復旧の coef（0.1 で生存率25点揺れるナイフエッジ）/ 探索の経済（cost・帰還率・報酬）/ 既存イベントのベース weight 関数 / 選択イベント4件の weight
- バランスのレバー特性（docs/20 §8 の詳細を必ず読むこと）: fpu・decay の緩和は熟練を大きく引き上げる / アクト倍率の強化は熟練より FR を先に壊す / slack のゲージ条件（士気等）は選別度が低い / 無作為の生存は配置由来の食料収入で頭打ち（許容レバー内では 5% に届かない。これが v1.4 の結論）
