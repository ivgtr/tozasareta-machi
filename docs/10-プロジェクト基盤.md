# プロジェクト基盤: 孤立した町の30日間

実装に入るための環境・規約・品質基準・完了定義を定める。技術設計（06）とUI設計（07）で「未確定」「または」と残っていた項目を確定する。

---

## 1. スタック

| 用途 | 選定 | 備考 |
| --- | --- | --- |
| 言語 | TypeScript（`strict: true`） | `noUncheckedIndexedAccess` も有効 |
| UI | React 19 + Vite | ゲームコアはDOM非依存（06 §2） |
| 状態管理 | `useReducer` + Context | ターン制で更新が疎。外部ストアは不要。性能問題が出れば `useSyncExternalStore` へ移行 |
| スキーマ検証 | zod | セーブデータの検証・マイグレーション（§5） |
| テスト | Vitest | ゲームコアの単体・決定性・シミュレーション（06 §12） |
| Lint | ESLint + typescript-eslint | |
| Format | Prettier | |
| Node | 20 LTS 以降 | |

**確定**: 状態管理は `useReducer` + Context。reducer はゲームコアの `step` を呼び、history 管理と永続化を store 層で行う（06 §4.3）。

## 4. セーブ整合性

### 4.1 スキーマと検証

- `SaveData` を zod スキーマで定義。ロード時は必ず `schema.safeParse` を通す。
- `version` フィールドを必須とし、現行と不一致ならマイグレーション関数を通す。

```ts
const migrations: Record<number, (raw: unknown) => unknown> = {
  // 1 → 2 の変換...（将来）
}
```

### 4.2 破損時の挙動

- 検証失敗 / マイグレーション不能 → **そのセーブを破棄し、新規ゲームへ**（例外を画面に出さない）。
- `localStorage` への读写はすべて try/catch（プライベートモード等の例外に耐える）。

### 4.3 保存対象

- ゲームの `StoreState`（state + history）を `save-game` キーに。
- 設定（§6）は別キー `settings` に分離（ゲームデータと混ぜない）。

## 5. セッションフロー

```
タイトル（ブリーフィング, 08 §5.5）
  ├─ セーブあり → [再開] [新しいゲーム]
  └─ セーブなし → [新しいゲーム]
新しいゲーム → 確認ダイアログ（既存セーブ上書き警告）→ ゲーム開始
プレイ中 → commitDay ごとに自動セーブ
終了 → エンディング → セーブをクリア → タイトルへ
```

- **v1 はシングルスロット**（オートセーブ）。複数スロットは非目標（§9）。
- undo 用の history もセーブに含め、再開直後も巻き戻し可能にする。

## 7. アクセシビリティ基準

**WCAG 2.1 AA を目標**。

- **コントラスト**: レトロパレットは暗色背景ゆえ、主要ペアを実測で検証する。`--ink`(#e8ecff)/`--night-700`(#1c2258) は高コントラスト。`--ink-dim` は本文に使わず補足専用。シグナル色（amber/red/green）は状態を**色 alone で伝えず**、文字語/アイコンを併用（03・07）。
- **キーボード操作**:
  | 操作 | キー |
  | --- | --- |
  | 焦点移動 | Tab / Shift+Tab |
  | 任務スロット選択 | 矢印キー |
  | トークン配置/回収 | Enter |
  | ダイアログ確定/取消 | Enter / Esc |
- `focus-visible` の明示枠。タッチターゲット最小 44px（07 §5.1）。
- ログ・日報は `aria-live` で通知。
- `prefers-reduced-motion` で走査線点滅・雨・カウントアニメ・プレイバックを静止/即時化。

## 8. テストとCI

### 8.1 テスト方針（06 §12 を確定）

| 種別 | 対象 | 要否 |
| --- | --- | --- |
| 単体 | actions / settlement / events / ending | 必須 |
| 決定性 | 同seed+同行動→同state（StrictMode分裂の検出） | 必須 |
| シミュレーション | N自動プレイの不変条件（06 §12.3）+ バランス勝率 | 必須 |
| UI | スモーク（起動・commit）を1–2 | 軽量に |
| E2E / ビジュアルリグレッション | — | **v1 非目標** |

### 8.2 CI（GitHub Actions）

push / PR で次を実行: `install → typecheck → lint → test → build`。すべてグリーンをマージ条件にする。

## 9. v1 完了定義（DoD）

以下をすべて満たすとき v1 完成とする。

- [ ] ブラウザで30日のプレイが完走でき、4エンディングのいずれかに到達する
- [ ] 5任務への作業員割当（DnD + タップ + キーボード）と commitDay が動作する
- [ ] イベント20種が状態依存で発火し、理由つきで報告される
- [ ] undo・自動セーブ・再開が動作する
- [ ] 決定性テストとシミュレーション不変条件テストが通る
- [ ] `lint` / `typecheck` / `test` / `build` がグリーン（CI含む）
- [ ] デスクトップ3ゾーンとモバイル縦積みが崩れない
- [ ] a11y: キーボードで全操作可、reduced-motion 反映、状態を色以外でも伝達
- [ ] グラフィックはすべてアートスロットのフォールバック（灰色ボックス皆無）
- [ ] バランスは初期値+健全性調整済み（無作為プレイで時々生存、意図的プレイで安定勝利）

## 10. v1 非目標

スコープ creep 防止のため、以下は **やらない** と明示する。

- サウンド実装（設定枠のみ。ストレッチ）
- i18n（日本語のみ）
- E2E / ビジュアルリグレッションテスト
- 複数セーブスロット / クラウドセーブ
- シード共有 / リプレイ再生のUI（内部的な決定性は持つが機能化しない）
- 拡張コンテンツ（地区・派閥・交易・外交など 04 の項目）
- バランスの完璧な追い込み（初期値+健全性で出荷し、後から調整）
