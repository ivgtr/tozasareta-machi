# 経済再編とプレイ感改善

[経済とバランス](./09-経済とバランス.md)・[選択型イベント設計](./16-選択型イベント設計.md)・[期間修正イベント設計](./17-期間修正イベント設計.md) を改変し、実プレイのフィードバック4点（探索の発火・帰還の可視性・備蓄の枯渇・士気の停滞）に対応する計画。数値はすべて仮置きで、sim で確定する。

**状態: 実装済み（v1.3 / E1–E4 コミット済み）**

**実装結果（E4 確定値）**: 仮数値 `food.decay:5` / `morale.decay:2` / 炊き出し予算15 / procure 15→12 を採用。加えて **`foodPerUnit:4→5`** を追加（計画外のデカップリングレバー。人員比例の食料消費で、終盤に人員が増える熟練にのみ強く効く）。sim 実測: **熟練 47% / 無作為 3%**（40/60游戏）、熟練 53% / 無作為 1%（200/120游戏）。

**検討したが不採用**: 食料瀕死時の救済イベント（`emergency_ration`）を追加して無作為の底上げを試みたが、食料逼迫構成では熟練も閾値に到達して恩恵を受け（熟練 +10pt 以上）、熟練~50% の目標と衝突したため削除。食料圧を緩めると熟練が 80% 超に跳ねるため、無作為と熟練の完全な分離は現機構では達成不可。full_recovery は食料圧が電力・医療投資を圧迫し autoAssign では 0（要対応候補は docs/00「次のステップ」）。

## 0. フィードバック4点

| # | フィードバック | 根拠（実コード） | 対応 |
| --- | --- | --- | --- |
| 1 | 探索が実行不能時に発生する | expedition の `when`（events-data.ts）に備蓄チェックがない。cost(12) 未満でも発火し、選択肢が全て絞られ「見送る」だけ残る | expedition の `when` に `stockpile >= cost` を追加 |

## 1. 確定した方針

### 設計原則

1. **核を変えない**: 備蓄の緊張は強化。食料をメンテ必須にして「道路一強」を解消し、全資源が管理対象に戻る。
2. **純粋・決定的を保つ**: 減衰・procure・帰還スポットライト化はすべて step 内で完結。同じ seed + 同じ行動 = 同じ結果。
3. **数値は balance.ts**: food.decay / morale.decay / procure レート / soup 予算額はすべて BALANCE に集約。
4. **ゲート制**: E1–E4 各マイルストーン末にゲートを確認。1マイルストーン = 1コミット。
5. **既存構造を維持**: 選択イベント、Modifier 機構、到着/探索の構造は変更しない。

### 非目標

- 道路復旧の coef 変更（0.1 で生存率25点揺れるナイフエッジのため、食料減衰で代替）
- 探索の経済（cost・帰還率・報酬）の変更
- `SAVE_VERSION` の引き上げ（後述 §4: 変更なし）
- イベント weight の再調整（現状維持）

### 1.1 探索の発火ガード（#1）

`expedition` の `when` に `c.state.stockpile >= BALANCE.expedition.cost` を追加。発火自体が止まる（1行）。

### 1.2 帰還のスポットライト化（#2）

再生機構は「`event:*` source + `unit:{id}` ターゲット → arrival スポットライト（ポーズ+カード+続行）」を既に持つ（usePlayback.ts:32-38）。**機構無変更で**:

- settlement.ts の帰還 effect の source を `'settlement'` → `'event:expedition_return'` に変更
- 帰還 effect 群に `unit:{id}` ターゲットの effect を混ぜる → buildBeats が自動でスポットライト化

RNG 消費は現状通り settlement 内なので決定性は不変。帰還専用コピー（「◯◯が帰還した」+成果）は任意拡張。

### 1.3 経済再編（#3）

**方針**: 予算=唯一の希少ハブ / 食料=漏れるバケツ / 備蓄=「明日のために貯める」対象 / 士気=予算競争の一員。

| レバー | 内容 | 採用 |
| --- | --- | --- |
| L1 | **食料の減衰**（新規）。power(10)/medical(8) と同じ流儀の固定値。道路復旧が「食料メンテ」になり永続解決を消す | ✅ |
| L2 | 道路復旧の coef 引き下げ（ナイフエッジ） | ❌ L1 で代替 |
| L3 | **炊き出しコスト: 備蓄15 → 予算15**。士気が電力・医療と同じ予算競争に入る | ✅ |
| L4A | **常設トグル「備蓄を調達」**（DecisionBoard、ration と対）。予算→備蓄の毎日の戦略判断 | ✅ |
| L4B | **trade_offer に `buy_stockpile`**（予算15 → 備蓄+12）追加 | ✅ |
| — | 食料上限超過→備蓄転換 | ❌ 道路一強を加速するため却下 |

### 1.4 士気の基底減衰（#4）

`morale.decay` を新設（仮: 2/日、「孤立生活のストレス」）。安定時は 基底-2 + calm+2 = 差し引き0（均衡）。上げるには炊き出し/好イベントが必要。放置すると prodHighAt(50) を割り生産低下。

### E1 詳細手順（コア経済変更）

1. `balance.ts`: `food.decay: 5`、`morale.decay: 2`、`tasks.soup_kitchen: { budget: 15 }`、`procure: { budget: 15, stockpile: 12 }` を追加。`soup_kitchen.stockpile` を削除。
2. `types.ts`: `DayPlan` に `procure: boolean` 追加。
3. `settlement.ts`: 食料減衰（consumption 適用後に `food.decay` を適用、power/medical と同じ流儀）、士気減衰（`morale.decay` を calm と同じブロックに）、procure 処理（`plan.procure` 時に budget → stockpile 変換）。
4. `actions.ts`: `taskCost` の `soup_kitchen` を stockpile → budget に変更（cost 表示・preview・autoAssign は自動追随）。
5. `events-data.ts`: `expedition` の `when` に `c.state.stockpile >= BALANCE.expedition.cost` 追加。
6. テスト: 食料減衰・士気減衰・procure・expedition ガードの単体テスト。settlement.test.ts の期待値更新。ui.test.tsx「備蓄不足で炊き出し」は E3 で扱う（ここでは型・コアのみ）。

### E2 詳細手順（帰還スポットライト + 交易）

1. `settlement.ts`: 帰還 effect の source を `'event:expedition_return'` に変更し、`unit:{id}` ターゲットを混ぜる（スポットライト化）。
2. `events-data.ts`: `trade_offer` に `buy_stockpile` 選択肢追加（予算15 → 備蓄+12、`when: budget >= 15`）。
3. `manifest.ts`: `expedition_return` の art spec 追加。
4. `docs/08` §4.5 対応表に反映。
5. テスト: 帰還 effect の source/target、buy_stockpile の発火/効果。

### E3 詳細手順（UI）

1. `DecisionBoard`: ration トグルと対の「備蓄を調達」トグル追加（DayPlan.procure を buildPlan に含める）。
2. コスト表示: 炊き出しが予算表示になるのは E1 の taskCost 変更で自動追随。
3. UI テスト: トグルの表示/動作、炊き出し予算不足の表示、ui.test.tsx「備蓄不足で炊き出し」を予算不足に書き換え。

### E4 詳細手順（sim で数値確定）

1. `food.decay` 感度: 3 / 5 / 8 で sim 回転。無作為2–10% を維持する値を採用。
2. `morale.decay` / `procure` レート / `soup` 予算額の確認。士気が prodHighAt(50) を適度に割る程度を確認。
3. 目標: 熟練〜50%（45–55%）、無作為2–10%、全4END到達。既存 sim 統計（イベント発火・modifier 有効日数）を活用。
4. 確定した数値を balance.ts に反映。

### 影響を受ける既存テスト

- **ui.test.tsx「備蓄不足で炊き出しが支払不能」**: 炊き出しが予算化されるため前提が変わる（備蓄不足→予算不足に書き換え、E3）。
- **settlement.test.ts**: 食料減衰・士気減衰の追加で期待値更新（E1）。

## 4. セーブ互換性

- **変更なし（`SAVE_VERSION=5` のまま）**。`DayPlan.procure` は永続化されない（GameState/history に含まれない日次入力）ため型追加で影響しない。
- 食料減衰・士気減衰・炊き出し予算化は balance 値の変更のみで GameState の型を変えない。
