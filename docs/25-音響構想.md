# 音響構想（将来拡張）

> 位置づけ: **構想段階**。着手は Issue #1（町中心UI・Phaser 移行）クローズ後。docs/22 §2 の「音響は非目標」はこの Issue の範囲限定であり、本作の将来像としては音響導入を見込む。本ドキュメントは方向性・トリガー契約・先行準備を定め、実装時に再設計する。

## 0. 方針

- 音は**補助チャネル**。情報の正は視覚（バッジ・町の変化）のまま変えない（docs/22 §8「バッジを正」と同原則）。音だけが唯一の情報源になる演出は作らない
- コアコンセプトに沿う: 音は「今日を生き延びるか、明日に温存するか」の**緊張を深める**ために使う。装飾的な賑やかしは増やさない（docs/README コアコンセプト）
- 世界観と整合するレトロ路線: 16bit 風チップチューン/アンビエント。既存の CRT・ピクセル表現（docs/07 §2）と並んでも浮かない音
- ゲームコア（`src/game/`）は**今後も無音のまま**。音は Phaser シーン側の演出層に閉じる（赤線の維持）

## 1. 構成（案）

| 層 | 内容 | 状態連動 |
| --- | --- | --- |
| 環境BGM | 夜の町の基底ループ（静・抑制） | アクト進行で緊張レイヤーが重なる（膠着期/正念場。docs/22 §7.3 の空アクト連動と同期） |
| 危機BGM | 危険状態（food 0 / morale < riotAt）のループ | danger 判定に連動して切替 |
| UI効果音 | 選択・配置・確定・取消・不可 | 操作フィードバック |
| イベント効果音 | threat / boon / arrival / 探索帰還の分類別 | playback のビート（docs/22 §7.2）に同期 |
| 警報音 | 崩壊前兆・死亡・アクト遷移 | aria-live 告知（docs/22 §11）と同時発火 |

- ループBGMは少数（基底・危機の2ループ+アクト叠加分）に抑え、重ね引きで状態を表現する（曲数を増やさない）
- イベント効果音はイベント個別ではなく**トーン分類単位**（threat/boon/arrival 等）で使い回す。新規イベント追加時の制作コストを一定にする

## 2. トリガー契約（先行準備の要点）

音の発火点は、町演出のために作る **fx対応表（docs/22 §7.1）と playback ビートに統合する**:

- fx対応表は `(source, target) → { 施設, 演出種 }` だが、実装時に**`sfx` フィールドを後から追加できる形**（イベント別の個別発火ではなく、写像テーブル経由の一括解決）で設計する。音導入時に発火機構を作り直さないため
- playback の flow/event/arrival ビートはそのまま音のキューポイントになる（ビート機構は変更しない）
- この制約は Issue #1 の実装コストを増やさない（docs/24 P5 に注記済み）

## 3. 技術方針（案）

- **Phaser 3 のサウンドマネージャ**を使う（Web Audio / フォールバック Audioタグ。Phaser 移行の副次的利点）
- モバイルの自動再生制限対策: 最初のユーザー操作で AudioContext を resume する（タイトル画面の「指揮所へ」押下が自然な解禁点）
- 形式は mp3（必要なら ogg 併用）。アセットは `src/assets/audio/`、命名は `bgm/{id}.mp3` / `sfx/{id}.mp3`（docs/22 §9.2 の kind 拡張）
- 設定は `settings` に `sound: boolean`（必要なら音量）を追加（現 `animations` トグルと同じ流儀。docs/24 付録A の設定トグルと並列）
- サイズ予算の目安: BGM 各 1–2分・低ビットレートで数MB以内。デプロイ先（GitHub Pages）の容量を意識する

## 4. 制作の流儀（着手時に確定）

docs/14・15・23 と同じトラック分離を踏襲する想定:

- アセット契約（曲想・長さ・ループ可否・音量基準）を先に固定
- 共通の音質基準（ビットレート・ラウドネス）を定め、1アセット1生成/制作コール
- 聴覚に依存しない検証（音なしでも全情報が分かること）をゲートに含める

## 5. 非目標（構想の範囲）

- 音声・ナレーション
- 適応的音楽（リアルタイム作曲・ステム多重の動的ミキシング）— アクト重ね引きまでは許容、それ以上は別検討
- ユニット個別のテーマ曲
- ゲームコア側への音関連 state の追加（表示都合の state 禁止の赤線は維持）
