# グラフィック設計書: 孤立した町の30日間

UI に必要なグラフィックのアセット戦略。初期はコード生成のプレースホルダで成立させ、将来はAI生成画像へ**ファイル追加だけ**で差し替えられることを保証する。

---

## 1. 方針と確定事項

| 項目 | 決定 |
| --- | --- |
| 基本戦略 | 2トラック制（コード描画 / 画像スロット） |
| アイコン | 全スロットを割り当てる。**手描きSVGは作らず「文字タイル」プレースホルダ**で描画 |
| 仮画像方式 | 統一テンプレート + アートスロット・フォールバック |
| 町のスカイライン | 採用。状態連動する「生きた」要素。デフォルトは手続き的SVG、`assets/skyline/` に画像があれば差し替え |
| AI生成 | 将来対応。スタイルガイド + プロンプト雛形を本設計書に同梱 |

---

## 2. 2トラック制

背景は「**情景（差し替え可能なアート）**」と「**状態エフェクト（手続き的で状態に反応する層）**」に分けて考える。情景はAI画像に差し替え可能とし、雨・走査線・ヴィネット・危険パルスなどの状態エフェクトはコードのまま残す。

| トラック | 内容 | 描画手段 | 将来のAI画像 |
| --- | --- | --- | --- |
| **A: コード描画** | UIプリミティブ（パネル/ボタン/ゲージ/カーソル/トークン）、状態エフェクト（雨/雲/走査線/ヴィネット/グローム/危険パルス） | CSS / SVG / Canvas | 差し替え不要（状態に反応するため） |
| **B: 画像スロット** | アイコン、肖像、イベントカード、エンディングKV、ブリーフィング背景、**背景シーン**、**スカイライン** | 現在はプレースホルダ（手続き的描画）、将来はビットマップ | スロットごとに生成して配置 |

トラックBのすべては**同一のフォールバック機構**（§3）を通す。背景シーンとスカイラインもBに属し、画像が置かれればそれに差し替わる。**画像がない間は手続き的描画がフォールバック**として機能するため、見た目は常に成立する。

## 3. アートスロット・フォールバック機構

### 3.1 解決順序

すべてのイラストは `kind` + `id` で参照する。実ファイルがあればそれを、なければプレースホルダを描く。

```tsx
<PixelArt kind="event" id="refugees" />
// 1) assets/event/refugees.png が存在 → <img>（image-rendering: pixelated）
// 2) なければ → PlaceholderArt（マニフェストの glyph + color で描画）
```

### 3.2 配置規約と自動検出

```
src/ui/assets/
  icon/{id}.png        # 48×48
  event/{id}.png       # 128×80
  portrait/{id}.png    # 48×48
  ending/{id}.png      # 192×108
  briefing/{id}.png    # 320×180
  scene/{id}.png       # 背景シーン（任意。なければ手続き的グラデーション）
  skyline/{id}.png     # スカイライン（任意。なければ窓が連動するSVG）
```

Vite の `import.meta.glob('../assets/**/*.png')` で起動時にルックアップを構築する。**PNGを置けばコード無変更で自動反映**される。これが「AI画像を足す = ファイルを置くだけ」の根拠。

### 3.3 マニフェスト

各スロットはコード側のマニフェスト（データ）で宣言され、プレースホルダはこれを読んで描画する。

```ts
interface ArtSpec {
  id: string;
  kind: 'icon' | 'event' | 'portrait' | 'ending' | 'briefing' | 'scene' | 'skyline';
  glyph: string;    // フォールバックの文字
  color: string;    // デュオトーン/枠の色トークン
  label: string;
}
```

## 5. プレースホルダのデザイン

灰色ボックスにはしない。題材（災害対策本部）に沿った「資料/写真」表現で統一する。すべてコード生成、ビットマップ不要。

### 5.1 文字タイル（アイコン）

JRPGの漢字アイコンに倣う。ピクセル枠のチップ中央に1文字。

```
┌───┐
│ 食 │   枠: ピクセル3px（frame-hi / frame-lo）
└───┘   文字: DotGothic16 700、色 = カテゴリカラー
        背景: night-700 + 下部へデュオトーン減衰
```

- サイズは CSS 変数で sm(20px) / md(28px) / lg(40px)。
- 文字はあくまで**識別子**であり、AI画像が届けば同じスロットに差し替わる。

### 5.2 イベントカード

無線写真/捜査資料を模す。

```
+--------------------------+
|   [デュオトーン背景]      |
|        ( 人 )            |  中央に文字タイル(lg)
|   ▓▓▒▒░░ ディザ ░░▒▒▓▓   |  ムード色のディザパターン
| ─走査線─                  |
| 避難者             [PHOTO/現像中] |  左下ラベル+右上スタンプ(cyan)
+--------------------------+
```

- 背景 = `night-800 → ムード色` のデュオトーン。
- イベントごとに「文字 + 色」が異なるため、20枚が個別に見える。

### 5.3 肖像

```
┌────┐
│ ◔◡◔ │  人物シルエット（CSS/SVGの汎用バスト）
│ 医  │  下部に役割の文字タイル
└────┘   枠色 = 役割カラー
```

### 5.4 エンディングKV

結末名を Press Start 2P / DotGothic で大きく + デュオトーン + 走査線。4結末は個別のムード色（完全復旧=green、管理された犠牲=amber、住民自治=cyan、崩壊=red）。

### 5.5 ブリーフィング背景（作戦地図）

ビットマップなしで「非常時」を出す。CSS/SVG で描く作戦地図:

- 暗いグリッド（地図の緯度経度風）
- 町のマーカー（ピクセルの点）
- **寸断された道路線**（途中で途切れた破線 = 孤立のメタファ）
- 点滅する事故マーカー（赤、ステップ点滅）
- 走査線 + 隅の「緊急派遣要請」スタンプ

## 6. 町のスカイライン（生きた要素）

状態を「町の眺め」として表示する、題材固有のレイヤー。右カラムの独立した「町の様子」パネルに帯状の**山村シルエット**を描く。画像は**状態別3バリアント**で、電力・危険フラグに応じて切り替わる。制作契約は [15-スカイライン画像計画](./15-スカイライン画像計画.md) を参照。

- **状態別バリアント**（`assets/skyline/{id}.png`）:
  - `town_normal` — 電力 ≧ 30。数軒の窓が琥珀色に点灯。
  - `town_dark` — 電力 < 30。ほぼ消灯の停電状態。
  - `town_danger` — 危険（士気<20 or 食料0）。赤系の非常灯。
  - 選択順: `town_danger` → `town_dark` → `town_normal`。解決しなければ汎用 `town.png`、それも無ければ手続き的SVGへフォールバック。
  - 3枚は**同じ構図・同じ屋根並び**で生成し、窓の灯りと差し色だけを変える（切替の違和感をなくす）。
- **状態連動**:
  - 画像: バリアント切替は**閾値ベース**のフィードバック（個別窓の連続連動はしない）。
  - 士気低下（<40）→ 画像・SVGとも `brightness/saturate` フィルタで暗く沈む。
  - 手続き的SVGフォールバックは、点灯窓の比率が電力に比例（`litRatio = power/100`）。
- **手続き的フォールバック**: 切り妻屋根の家屋・祠・無線塔（ビーコン点滅）・松・山並みを SVG で生成。画像未着時もビル群ではなく山村に見える。
- **配置**: PlayScreen の右カラムにある独立した「町の様子」パネル。デスクトップでは「本部記録」の下、タブレットでは記録と横並び、モバイルでは「町の状況」の後かつ「本部記録」の前に置く。

背景シーン（`assets/scene/night.png`）も同様で、**画像があればそれを、なければ手続き的グラデーション（夜空+雲）**を描く。雨・走査線・ヴィネットなどの状態エフェクトは常にコード描画のまま重ねられる。

## 7. AI生成スタイルガイド + プロンプト雛形

### 7.1 全スロット共通スタイルガイド

生成物がレトロUIと乖離しないための固定制約。

- **解像度**: スロットごとのピクセル原寸（§3.2）。拡大表示は `image-rendering: pixelated`。
- **共通の暗部**: `#0a0e24 #131740 #1c2258` を全スロットの基調とする。
- **UI/アイコン用パレット**: `#0a0e24 #131740 #1c2258 #e8ecff #ffc857 #ff5f66 #5ee6a8 #6fd8ff #ffd94a`。小面積で即識別が必要な記号に使う。
- **情景用パレット**: `#0a0e24 #131740 #1c2258 #405474 #6f849b #aeb7c5 #a87345 #7f4550 #c79a60`。イベント、シーン、ブリーフィングなど、面積の大きい画像に使う。
- **作風**: 16-bit ピクセルアート。可視ディザリング。**アンチエイリアスなし**（輪郭はくっきり）。
- **雰囲気**: 夜の孤立した小さな町、災害対応の緊張感。色相差ではなく、明度差、光源、シルエットで主題を読ませる。
- **禁止**: 実写調、グラデーション多用、ネオン的な補色対比、現代的なUI要素の描き込み。

### 7.2 情景画像の色設計

イベント画像では、「色数を減らす」よりも「色の役割を減らす」ことを優先する。同じ画面で green / gold / red / cyan が別々の焦点を作ると、災害対応ではなく祭りやサイバーパンクの印象に寄る。

- **1枚1アクセント系統**: 主役は「冷たい青灰」「鈍い琥珀」「くすんだ錆色」のいずれか1系統。第2アクセントは光源または非常信号に限る。
- **UI意味色を風景に塗らない**: green=好機、red=危険などのトークンはUIが伝える。人物、建物、山をトークン色で面的に塗らない。
- **光源を先に決める**: 月光・雪明かりは青灰、窓・ランタンは鈍い琥珀、非常灯は少量の錆色とする。物体ごとに色を変えない。
- **面積の目安**: 暗部 80〜90%、主アクセント 8〜15%、第2アクセント 3%以下。UI用の高彩度色を例外的に入れる場合は1%以下。
- **明度で判別**: 32px相当のサムネイルまたはグレースケールで、主題が背景から読めること。鮮やかな輪郭色で判別させない。
- **「低彩度化」で終わらない**: 競合する色相をそのまま暗くしても、視線の分散は残る。不要な色系統を青灰または暗部へ統合する。

#### 既存画像の改善手順

1. 原図の主題、光源、視線誘導を言語化する。
2. 競合する色系統を特定し、残す1系統と第2アクセントを決める。
3. 色だけ変える場合は構図・人物数・シルエットを不変条件とする。再生成案がこれを破ったら採用しない。
4. 原画像を上書きせず候補を作り、原寸と実表示倍率の両方で比較する。
5. 1枚ずつ承認し、承認後にのみ実スロットへ反映する。一括変換は行わない。

### 7.3 スロット別プロンプト雛形

```

16-bit pixel art, scenic palette (#0a0e24,#131740,#1c2258,#405474,
#6f849b,#aeb7c5,#a87345,#7f4550,#c79a60), visible dithering,
no anti-aliasing, crisp pixels.
Night scene of an isolated small town during disaster response:
{イベント内容の1文}. Dominant accent family: {冷たい青灰 / 鈍い琥珀 /
くすんだ錆色のいずれか1つ}. Use only this dominant accent family.
Establish one physical light source and use value contrast, not multiple
saturated hues, to direct attention. Dark areas cover roughly 80-90% of the
image. A secondary accent, if any, is confined to the light source or an
emergency signal. Small silhouetted figures, restrained and tense. Avoid
neon green/gold/red/cyan competition. {補足}.

[PORTRAIT / 48×48]
```

### 7.4 生成時の検証チェックリスト
