## プロジェクト概要

**孤立した町の30日間** — ブラウザで動くターン制運営シミュレーション。災害で孤立した町の臨時対策責任者として、ユニット（人員）を任務に配置し、30日間の再接続を耐え抜く。

- 技術: Vite + React 19 + TypeScript(strict) + Vitest
- 詳細設計: `docs/01`〜`docs/19`（`docs/README.md` が目次）

### v1.3 の詳細（最新作業）

方針: 「**予算=唯一の希少ハブ / 食料=漏れるバケツ / 備蓄=明日のために貯める対象 / 士気=予算競争の一員**」。

- **E1 コア経済**: 食料減衰 `food.decay:5`（power/medical と同じ流儀の固定値。道路復旧が「食料メンテ」になり永続解決を解消）/ 士気基底減衰 `morale.decay:2`（calm+2 と均衡し安定時は差し引き0。放置すると prodHighAt(50) を割り生産低下）/ 炊き出しコストを 備蓄15 → 予算15 に変更（士気が電力・医療と予算競争に入る）/ 常設トグル「備蓄を調達」`procure`（予算15→備蓄12、`DayPlan.procure`、ration と対）/ trade_offer に `buy_stockpile`（予算15→備蓄+12）
- **E1 探索ガード**: expedition の `when` に `stockpile >= cost` を追加。実行不能時の発火を止める
- **E2 帰還スポットライト**: 探索帰還 effect の source を `event:expedition_return` に変更し `unit:{id}` ターゲットを混在 → 再生機構が自動で arrival スポットライト化（ポーズ+カード+続行）。死亡時は unit ターゲットなしのイベントビート。ArrivalOverlay は帰還時 kicker「探索から帰還した」
- **E3 UI**: DecisionBoard に「備蓄を調達」トグル（炊き出しは予算表示へ自動追随）
- **E4 バランス確定**: `foodPerUnit:4→5`（人員比例の食料消費。終盤に人員が増える熟練にのみ効くデカップリングレバー）。**検討したが不採用**: 食料瀕死時の救済イベントは、食料逼迫構成では熟練も閾値に到達して勝率を押し上げたため削除（詳細は docs/19 冒頭）
- **full_recovery の到達性（解決済み）**: v1.3 の食料圧の下で autoAssign は 0 だが、**狙ったプレイでは到達可**（`tests/full-recovery.test.ts`: 熟練simと同じseedで **37/60** 到達）。バランス無変更で決着。詳細は docs/19 §7

### ゲームシステム要点（現行）

- **期間修正（Modifier）**: `GameState.modifiers` に期間付き効果を保持。`modifiers.ts` のクエリ（`queryMult`/`queryAdd`/`isTaskDisabled`/`tickModifiers`）で settlement/actions が参照。ターゲット文字列（`consume:food`/`decay:power`/`produce:{task}`/`produce:all`/`income:budget`/`drain:stockpile` 等）×演算（mult/add/set）の汎用設計。任務ロックは `produce:{task}` set 0
- **選択型イベント**: `EventDef.kind:'choice'`。発火で `phase:'choice'` に一時停止、`resolveChoice` で再開。選択肢は `when` でフィルタ。探索は `perUnit` で動的選択肢
- **探索**: 備蓄前払い（`cost:12`）で送出 → 数ターン不在（労力不可・食料消費0）→ 毎日帰還抽選（`minDays` 後から、日数で帰還率上昇）→ 適性で成果決定（大成功=4日分/成功=1日分/危険=負傷・死亡/失敗）。不在ユニットは清算・表示から除外
- **経済**: 士気→生産倍率（`moraleMult`、prodHighAt 50）。予算収入 = `income:30` + `bonus:15`（電力≥`bonusAt:50`）。食料は毎日 `food.decay:5` 減衰 + 在籍人員×`foodPerUnit:5` 消費

### 中核の契約

- `step(state, action)` は**純粋**。同じ seed + 同じ行動 = 同じ結果（決定性テストで保証）。
- 1日の解決は `commitDay` → 任務効果 → 清算（procure・食料/士気減衰・探索帰還解決含む）→ イベント → 日付進行。
- **選択イベント**: 発火すると `phase:'choice'` で一時停止し、`resolveChoice` アクションで再開する。探索は `perUnit` で動的選択肢を生成。
- 再生（`usePlayback`）は**ビート単位**: `flow`（定常増減=レポートへ流す）/ `event` / `arrival`（後者は**スポットライト=ポーズ+カード+続行**）。探索帰還は `event:expedition_return` + `unit:{id}` で arrival 扱い。

## 主要な設計決定（要約）

- **作業員→ユニークユニット**: 名 + 二つ名 + 4適性(労/技/医/魅) + 特性 + フレーバー。配置は「誰をどの任務へ」の一段。
- **ユニークパロディ**: 30体を実在人物（故人）15 + アニメ/ゲームキャラ15のパロディに。名前は1文字ズラし、フレーバーは元ネタ参照。初期4体はオリジナルのまま。
- **統合到着抽選**: 30体ユニークプール + ランダム生成の混合抽選。重みは日数逓増、確定受け入れ、上限10、ユニークは重複なし（`flags.joinedUniques`）。
- **汎用肖像**: ランダム加入者に8枚プールから決定的割り当て（seed+unitId ハッシュ、RNG非消費）。
- **選択型イベント**: `EventDef.kind:'choice'` + `choices`/`perUnit`。発火で `phase:'choice'` 停止、`resolveChoice` で再開。
- **探索の経済**: 備蓄前払い・数ターン不在・毎日抽選帰還・適性で大成功(4日分)/成功(1日分)。不在ユニットは清算・表示から除外。
- **期間修正（Modifier）**: ターゲット文字列×演算（mult/add/set）の汎用機構。参照側にクエリ点を追加するだけで新効果に対応。
- **v1.3 経済再編**: 予算を唯一の希少ハブに。食料は減衰で「漏れるバケツ」、備蓄は procure/buy_stockpile で「貯める対象」、士気は炊き出し予算化で「予算競争の一員」。foodPerUnit は熟練狙い撃ちのデカップリングレバー。
- **バランス**: `BALANCE`（`src/game/data/balance.ts`）に一元化。実測 熟練〜47%/無作為〜3%（v1.3・硬派）。期間の日数・倍率は `BALANCE.modifier`。

## 規律・注意点

- **フェーズごとにコミット**（`docs/11` 参照。1フェーズ=1コミット、CI緑を条件に）
- **数値は `balance.ts` に集約**。ロジックにマジックナンバーを書かない
- **コードにコメントは原則追加しない**
- **韓国語混入に注意**（過去に `소식`/`균형`/`바로` が混入した）。懸念があれば `[가-힣]` でgrep。中国語漢字（「游戏」等）の混入も過去に起きたため、不自然な漢字に注意
- セーブは zod スキーマ（`SAVE_VERSION=5`）。非互換の旧セーブは破棄→新規ゲーム
- `src/game/` は DOM非依存（lintで強制）。UIからコアへの一方向依存を守る
- **バランス調整の知見（v1.3 E4）**: random と skilled は食料で強く相関し、汎用レバー（food.decay/income/士気）は両方を同方向に動かす。skilled のみを下げるには foodPerUnit（人員比例）が有効。救済イベントは食料逼迫構成では熟練も恩恵を受けデカップリング不可。詳細は docs/19
