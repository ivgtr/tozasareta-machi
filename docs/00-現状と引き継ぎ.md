# 現状と引き継ぎ

次のセッションで作業を続けるための現状把握ドキュメント（`AGENTS.md` がここへ誘導する）。`docs/README.md`（設計ドキュメント目次）とあわせて読むこと。

## プロジェクト概要

**孤立した町の30日間** — ブラウザで動くターン制運営シミュレーション。災害で孤立した町の臨時対策責任者として、ユニット（人員）を任務に配置し、30日間の再接続を耐え抜く。

- 技術: Vite + React 19 + TypeScript(strict) + Vitest
- 詳細設計: `docs/01`〜`docs/18`（`docs/README.md` が目次）

### v1.2 期間修正イベント（直近セッションの主成果・docs/17）
- **Modifier 機構**: `GameState.modifiers` に期間付き効果を保持。`modifiers.ts` のクエリ関数（`queryMult`/`queryAdd`/`isTaskDisabled`/`tickModifiers`）で settlement/actions が参照。ターゲット文字列（`consume:food`/`decay:power`/`produce:{task}`/`produce:all`/`income:budget`/`drain:stockpile` 等）× 演算（mult/add/set）の汎用設計で、将来の効果追加が型変更なしで済む
- **ライフサイクル**: イベント発火日に `mutate`+`addModifier` で生成（`startDay`/`daysLeft`）。`finalizeDay` で確定日の day を渡してデクリメント（発火日は減らない）。0で除去
- **自動イベント22件追加**: 特大ラッキー4（manna/supply_drop/hot_spring/miracle_harvest）/ ラッキー6（sunny_stretch/animal_trap/traveling_engineer/volunteer_surge/clean_water/cached_fuel）/ バッド9（typhoon/storage_flood/generator_overheat/landslide_actual/food_spoilage/cold_snap/rumor/rat_infestation/insomnia）/ 連鎖3（aftershock/second_wave/gratitude）。期間修正系は任務ロック・消費0・減衰倍率・毎日drain等を表現
- **イベント統合（先行作業）**: trader/blackout のランダムイベントを削除し、trade_offer/power_crisis の選択イベントへ一本化。generator_failure は power>50 に引き上げ（突然の機械故障として差別化）。アートは trader.png→trade_offer.png / blackout.png→power_crisis.png へ流用
- **UI**: DecisionBoard で disabled な任務をグレーアウト+理由表示（「台風接近（あと2日）配置不可」）し配置を拒否。StatusWall に modifier バッジ（ラベル+残り日数+ムード色）

### 選択型イベント（docs/16）
- **決定フェーズ**: 選択イベント発火で `phase:'choice'` に一時停止、`resolveChoice` アクションで再開。純粋・決定的を維持（`pendingEvents` キュー方式）
- **交易/危機**: 資源の弁（トレード）/トレードオフを選ぶ。見送り・断るも delta0 効果で本部記録に残る
- **探索（再設計済み）**: 備蓄前払い（`cost:12`）で送出 → **数ターン不在**（労力不可・食料消費0）→ **帰還は毎日抽選**（最短 `minDays` 日後から、日数で帰還率上昇・ランダム）→ 成果は**適性で決定**（大成功=4日分 5-10% / 成功=1日分 30-60% / 危険=負傷・死亡 / 失敗）。報酬は帰還日数ボーナス+分散（×0.7-1.3）。探索中は探索イベント非発生
- **探索中ユニットは清算から除外**: 食料消費/餓死/離脱/popular・troublemaker士気/回復のいずれも不在ユニットを計上しない（表示も StatusWall・TopBar で整合）
- **経済をイベント主軸へ**: 士気→生産倍率（低士気で生産低下）+ 任務係数引き締め（1.0）

### 中核の契約

- `step(state, action)` は**純粋**。同じ seed + 同じ行動 = 同じ結果（決定性テストで保証）。
- 1日の解決は `commitDay` → 任務効果 → 清算（探索帰還解決含む）→ イベント → 日付進行。
- **選択イベント**: 発火すると `phase:'choice'` で一時停止し、`resolveChoice` アクションで再開する。探索は `perUnit` で動的選択肢を生成。
- 再生（`usePlayback`）は**ビート単位**: `flow`（定常増減=レポートへ流す）/ `event` / `arrival`（後者は**スポットライト=ポーズ+カード+続行**）。イベントはすべてポーズする統一UX。

## 主要な設計決定（要約）

- **作業員→ユニークユニット**: 名 + 二つ名 + 4適性(労/技/医/魅) + 特性 + フレーバー。配置は「誰をどの任務へ」の一段。
- **ユニークパロディ**: 30体を実在人物（故人）15 + アニメ/ゲームキャラ15のパロディに。名前は1文字ズラし、フレーバーは元ネタ参照。初期4体はオリジナルのまま。
- **統合到着抽選**: 30体ユニークプール + ランダム生成の混合抽選。重みは日数逓増（`arrivalBase + day×arrivalPerDay`）、確定受け入れ、上限10、ユニークは重複なし（`flags.joinedUniques`）。
- **ランダム名**: 和風単名/姓名/西洋名の混合生成。二つ名はピーク適性由来（力自慢/発明家/薬草通/人たらし）。
- **汎用肖像**: ランダム加入者に8枚プールから決定的割り当て（`selectRandomPortrait`、seed+unitId ハッシュ、RNG非消費）。未使用優先、枯渇時は全復活。
- **ユニーク判定**: `unique` フラグ（二つ名の有無ではない）。カードの二つ名行は常時表示で高さ統一。
- **選択型イベント**: `EventDef.kind:'choice'` + `choices`/`perUnit`。発火で `phase:'choice'` 停止、`resolveChoice` で再開。探索は `perUnit` で動的選択肢（ユニットごとに生成）。選択肢は `when` でフィルタ（perUnit も静的も。`choiceOptions` 内で評価）
- **探索の経済**: 備蓄前払い・数ターン不在・毎日抽選帰還・適性で大成功(4日分)/成功(1日分)。不在ユニットは清算・表示から除外。
- **期間修正（Modifier）**: ターゲット文字列×演算（mult/add/set）の汎用機構。個別 kind の enum を持たず、参照側（settlement/actions）にクエリ点を追加するだけで新効果に対応。任務ロックは `produce:{task}` set 0 で表現し、UI は実効値0を disabled 表示。
- **イベント統合**: trader/blackout のランダムイベントを trade_offer/power_crisis の選択イベントへ一本化。「行商人=交易の判断」「停電=政策判断」に統一し、generator_failure（即時大ダメージ）と役割分担。
- **バランス**: `BALANCE`（`src/game/data/balance.ts`）に一元化。実測 熟練〜53%/無作為〜3%（イベント42+4件・硬派）。期間の日数・倍率は `BALANCE.modifier`。

## 規律・注意点

- **フェーズごとにコミット**（`docs/11` 参照。1フェーズ=1コミット、CI緑を条件に）
- **数値は `balance.ts` に集約**。ロジックにマジックナンバーを書かない
- **コードにコメントは原則追加しない**
- **韓国語混入に注意**（過去に `소식`/`균형`/`바로` が混入した）。懸念があれば `[가-힣]` でgrep

- `src/game/` は DOM非依存（lintで強制）。UIからコアへの一方向依存を守る
