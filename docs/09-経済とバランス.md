# 経済とバランス: 孤立した町の30日間

技術設計書（06）で空いていた「値」と「経済の流れ」を定義する。すべての数値は **初期値** であり、06 §12 のシミュレーションで確定させる（`src/game/data/balance.ts` に集約）。本作は **オープン情報** のゲームである——悩みの本質は「数値の推測」ではなく「優先順位」なので、原則として数式と見込みはプレイヤーに開示する。

---

## 1. 経済の基本ループ

3つの操作レバー（作業員 / 予算 / 備蓄）と4資源（食料 / 電力 / 医療 / 士気）の流れ。

```
        ┌─ 作業員（毎日リセット・士気で増減）= 行動の「枠」
        │
予算 ───┴→ 発電修理 / 医療増員（コスト）
備蓄 ────→ 炊き出し（消費→士気）, 食料切れ時の緩衝
        │
道路復旧 → 食料 + 備蓄 を毎日搬入（生命線）
電力 ───→ 高いと予算ボーナス / 医療効率。低いと医療が減衰
医療 ───→ 低いと放置日数++→感染症、極低で死者
士気 ───→ 低いと作業員減・暴動、高いと協力者+1（正の循環）
```

意図する循環:

- **負の螺旋**: 士気↓ → 作業員↓ → 手が回らない → 資源↓ → 士気↓。放置すると崩壊する。
- **正の循環**: 士気≥70 → 協力者+1 → 行動力増 → 余裕。住民自治END への道。
- **食料の緊張**: 毎日必ず消費される。道路復旧に作業員を割かなければ数日で尽きる。「今日か明日か」の中核。

## 2. レバーのモデル

> **注**: 作業員・人員のモデルは [12-ユニット設計](./12-ユニット設計.md)（ユニークユニット + 適性駆動の効果 + 食料消費）に置換される。以下の §2.1〜2.3 と任務効果は旧モデル。数値の骨格（収入・消費・減衰）は踏襲するが、効果計算は 12 §5 を正とする。

### 2.1 作業員（行動の枠）

毎日リセットされる（人は戻る）。有効数は前の日の最終士気で決まり、計画時に表示する。

```
workers = base + (morale >= 70 ? +1 協力者 : 0)
                 - (morale < 40 ? 1 : 0)
                 - (morale < 20 ? 1 : 0)
workers = max(min, workers)
```

### 2.2 予算（毎日収入）

```
budget += income + (power >= powerBonusThreshold ? powerBonus : 0)
```

電力が復旧していると商業が回り増収——電力優先の間接的な見返り。

### 2.3 備蓄（戦略予備）

- 入手: 道路復旧で少量ずつ搬入 / イベント（隠し備蓄）。
- 消費: 炊き出し。
- 緩衝: 食料が尽きると**まず備蓄を取り崩して**飢餓を遅らせる。

## 3. 資源の計算式（清算で適用）

### 3.1 食料（在庫）

```
consume = food.consume × (本日配給を絞った ? 0.5 : 1)
food -= consume
food < 0 のとき:                       # 緊急予備
  food += stockpile; stockpile = 0     # 備蓄を食う
  まだ < 0 なら:
    shortfall = -food; food = 0
    casualties += ceil(shortfall / 10)
    morale += morale.hunger            # 大幅減
```

### 3.2 電力・医療（容量 0–100）

```
power  -= power.decay
medical -= medical.decay + (power < lowPowerThreshold ? lowPowerExtraDecay : 0)
```

### 3.3 医療放置・死者

```
medical < neglectThreshold ? flags.daysWithoutMedical++ : = 0   # 感染症の重みに寄与
medical < casualtyThreshold かつ 確率 p → casualties += 1
```

### 3.4 士気（指標 0–100）

清算時に以下を加算し clamp:

| 条件 | 増減 |
| --- | --- |
| 食料が尽きた（備蓄後） | hunger（大減） |
| 食料が残り lowFoodDays 日分未満 | lowFood（小減） |
| 本日配給を絞った | ration（減）+ daysFoodCut++ |
| medical < neglectThreshold | lowMedical（減） |
| power < 30 | lowPower（減） |
| 食料十分 かつ medical≥50 かつ power≥50 | calm（小増） |

```
morale >= coopThreshold → flags.cooperation++   # 住民自治END の累積
morale < riotThreshold → 暴動: budget -= riotBudgetLoss（理由つき）
```

## 5. 任務の定義

人員は任意で1名配置でき、**適性一致で効果増**。人物は1日1任務まで。

| 任務 | コスト | 効果（初期値） | 適性 |
| --- | --- | --- | --- |
| `repair_power` | 予算20 | `power += repairBase + repairPerWorker×w + (技術者 ? skill/8)` | 技術者 |
| `restore_road` | — | `food += foodPerWorker×w`、`stockpile += stockpilePerWorker×w` | — |
| `reinforce_medical` | 予算15 | `medical += (reinforceBase + reinforcePerWorker×w + (医師 ? skill/10)) × 電力係数` | 医師 |
| `soup_kitchen` | 備蓄15 | `morale += soupBase + (町長 ? skill/12)` | 町長 |
| `ration` | — | 本日消費×0.5、`morale += ration`(減)、daysFoodCut++ | — |

- 電力係数 = `power >= lowPowerThreshold ? 1.0 : 0.6`（停電下では医療が捗らない）。
- `rest`（待機）は任務として実装しない。**未割当 = 待機**とする（06のTaskId列挙から削除）。

### 5.1 人物と適性

| id | 名前 | skill | 適性任務 |
| --- | --- | --- | --- |
| `mayor` | 町長 | 60 | soup_kitchen（万能寄り） |
| `medic` | 医師 | 80 | reinforce_medical |
| `engineer` | 技術者 | 80 | repair_power |

## 6. 清算の順序（commitDay 内、確定版）

06 §5.2 の pipeline に数値適用順序を固定する。

```
1. 行動解決（§5 の任務効果）
2. 収入: budget += income + 電力ボーナス
3. 食料消費 + 緊急予備 + 飢餓（§3.1）
4. 電力・医療の減衰（§3.2）
5. 医療放置フラグ + 死者リスク（§3.3）
6. 士気漂移 + 協力者累積 + 暴動（§3.4）
7. イベント（06 §7: 重み付き1件）
8. day++、翌日作業員数の確定、終了判定（§7）
```

## 7. 閾値とエンディング

### 7.1 バランステーブル（`balance.ts` の初期値）

```ts
export const BALANCE = {
  days: 30,
  workers:  { base: 5, min: 2, volunteer: 70, penaltyA: 40, penaltyB: 20 },
  food:     { start: 100, consume: 20, perWorker: 9 },
  stockpile:{ start: 50, perWorker: 3, soupCost: 15 },
  budget:   { start: 100, income: 30, bonus: 15, bonusAt: 50 },
  power:    { start: 60, decay: 8, repairBase: 4, repairPerWorker: 5 },
  medical:  { start: 60, decay: 6, extraDecay: 2, lowPowerAt: 30,
              reinforceBase: 3, reinforcePerWorker: 4, neglectAt: 30,
              casualtyAt: 20, casualtyP: 0.3 },
  morale:   { start: 60, hunger: -15, lowFood: -3, lowFoodDays: 3, ration: -6,
              lowMedical: -3, lowPower: -2, calm: +1,
              riotAt: 20, riotBudgetLoss: 10, coopAt: 70 },
  tasks: {
    repair_power:      { budget: 20 },
    reinforce_medical: { budget: 15 },
    soup_kitchen:      { stockpile: 15, base: 6 },
  },
  ending: { collapseCasualties: 30,
            fullRecovery: { power: 70, medical: 70, maxCasualties: 5 },
            sacrificeCasualties: 10, selfGovernanceCoop: 18 },
}
```

### 7.2 終了判定

| 種別 | 条件 | 優先度 |
| --- | --- | --- |
| `collapse` | `morale <= 0` または `casualties >= collapseCasualties` | 随時（早期敗北） |
| `managed_sacrifice` | `casualties >= sacrificeCasualties` | 30日到達時・最優先 |
| `full_recovery` | `power >= fullRecovery.power かつ medical >= fullRecovery.medical かつ casualties < fullRecovery.maxCasualties` | 次 |
| `self_governance` | `cooperation >= selfGovernanceCoop` かつインフラ未復旧 | 次 |
| `managed_sacrifice` | 既定 | 最後 |

## 8. 情報開示方針（情報設計）

原則 **オープン情報**。プレイヤーは世界の仕組みを理解して優先順位で悩む（03）。

| 区分 | 内容 |
| --- | --- |
| **公開** | 全資源の現在値と状態語、毎日の消費量と予算収入、任務の効果見積（割当時の `+電力` 予測）、人物のskillと適性、翌日の作業員数、閾値が近い資源 |
| **半公開** | 危険の予兆（士気<30 で「抗議の気配」、医療放置で「感染症の懸念」など、閾値接近時のみヒント） |
| **非公開** | イベントの具体的な発生確率・重み、抽選結果（起きるまで不明）、乱数シード |

効果見積はコアに **予測関数** `preview(state, plan) => Effect[]` として実装し、UI が割当中に描画する。`step` とロジックを共有して乖離を防ぐ。

## 9. 難易度・ペーシング

- **第1–5日（立ち上がり）**: 食料が約5日で尽きる圧。道路復旧への初期投資を学ぶ。
- **第6–20日（中盤）**: 電力/医療の減衰とイベントが重なり、取捨選択が厳しくなる。
- **第21–25日頃**: `rescue_contact`（救援「あと5日」）が起こり得る。ゴールが意識され、温存か投資かの最終判断。
- **第26–30日（終盤）**: 到達できれば凌ぎ切り、30日目で評価。

難易度は「無視すると崩壊するが、適切に配分すれば勝てる」を狙い、シミュレーションで勝率を確認して調整する（目標: 無作為プレイで時々生き残る、熟練すれば安定）。
