## このセッションで得たノウハウ・注意点

- sim の `console.log` は `npx vitest run --testNamePattern simulation --reporter=verbose` でないと表示されない
- `tickModifiers`（modifiers.ts:29）は `day == startDay` の日は decrement しない。アクト境界の実効日は必ずテストで確認する
- `addModifier`（modifiers.ts:35）は id で重複排除 → D2 の冪等保証の要。旧セーブの途中再開（例: day 15）からも初回 finalize で補完される設計
- 選択イベントの optionId はイベントをまたいで一意（buy_food / divert_medical / distribute / send_* 等）。id の集合でイベントを判定できる（`tests/full-recovery.test.ts` に実例）
- CI は `format:check`（prettier）も走る。コミット前に `npm run format:check`
- **中国語・韓国語混入**: このセッションで docs/20 に簡体字「设计」が混入し検出・修正した。ドキュメント作成後は `grep -P "[가-힣]"` と不自然な簡体字の grep を習慣にする
- `tests/full-recovery.test.ts` は番人: アクト圧・脅威スケーリングが FR 率を下げると assertion が検出する（docs/20 §2.4 の設計意図と照らして判断）
