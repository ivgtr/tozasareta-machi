# 町アセット制作計画（アイソメ・Phase 4 最小セット）

[docs/22 町中心UI再設計](./22-町中心UI再設計.md) §9 に基づき、アイソメ町画面の **Phase 4 最小アセットセット**（地面ベース・施設・トークンの計25点）を制作するための画像制作者向け計画。アセット契約・生成プロンプト・ゲートを定める。docs/14（汎用肖像）・docs/15（スカイライン）と同じトラック分離・ゲート制の流儀を踏襲する。

---

## 0. 背景と目的

docs/22 の決定（Phaser フル移行・**斜め見下ろし 2:1 アイソメ**・生活感は中程度）を受け、町・施設・人物の**視点と縮尺を最初から固定**したアセットセットを制作する。アイソメは角度の機械的検証が難しいため、docs/14 §1.2 の「構図の固定条件」を**投影仕様の固定**として強化して適用する。

### 進め方の原則

- **先にアセット契約を固定**: 寸法・投影・パレット・レイアウトを合意してから生成する（§1）
- **基準先行・参照生成**: 町ベース → 基準施設（hq）→ 各施設の normal → 状態差分の順に固定し、後続はすべて承認済み参照のスタイルを継承する。**1アセット1生成コール**
- **透明背景の導入**: 施設・トークンは地面ベースへ重ねるため**透明PNG**。従来の不透明アセット（肖像・スカイライン）と扱いが異なる点に注意
- **既存アセットと同じ作品世界**: `scene/night.png`・既存イベント画像とパレット・ディザリング・光源を揃える
- 画像は `src/assets/{kind}/{id}.png` に置く（docs/22 §3.2 の構成。配置先は Phase 1 の Phaser 移行と同時でもよい）

### 非目標

- fx（煙・雨・火花等）の画像制作 — Phaser の粒子/グラフィックスで描画し、必要になったものから個別計画
- 歩く住民・群衆スプライト（docs/22 WB-3 で中程度=住民なしと確定）
- ユニーク30体の個別トークン — 汎用プールで代用（§1.4）
- イベント画像22件（docs/00 次のステップ#2、本計画の範囲外）
- **HUD・操作UIの枠画像**（ボタン枠・パネル枠・選択カーソル・配置可否表示・通知・ログドロワー）— Issue §D のこれらは画像アセットにせず、UIキットが手続き的に描画する（docs/24 P1）。画像を作るのは9-sliceでは済まない世界観要素に限る

## 1. アセット契約

### 1.1 投影・グリッド仕様（全アセット共通の正）

| 項目 | 指定 |
| --- | --- |
| 投影 | 斜め見下ろし、**2:1 ダイアモンド**（タイル 48×24 px） |
| 光源 | 夜の冷光が**左上**から、深い影は**右下**へ（`scene/night.png` と一致） |
| パレット | `#0a0e24 #131740 #1c2258 #e8ecff #ffc857 #ff5f66 #5ee6a8 #6fd8ff #ffd94a` の**9色以内** |
| 形式 | indexed PNG、アンチエイリアスなし、ディザリングあり |
| 後処理 | 生成物は近傍法で完成サイズへ縮小し、固定パレットへ量子化（docs/14 §3 手順6 と同じ） |

### 1.2 完成サイズ一覧（25点）

| kind | ID | 点数 | 完成サイズ | 背景 |
| --- | --- | --- | --- | --- |
| town | `base` | 1 | **480×320** | 不透明（空 `#0a0e24`） |
| facility | `hq-normal` | 1 | **96×112** | 透明 |
| facility | `power-normal` / `power-low` / `power-working` | 3 | 96×112 | 透明 |
| facility | `road-collapsed` / `road-working` / `road-restored` | 3 | 96×112 | 透明 |
| facility | `clinic-normal` / `clinic-working` | 2 | 96×112 | 透明 |
| facility | `plaza-normal` / `plaza-working` | 2 | 96×112 | 透明 |
| facility | `warehouse-normal` | 1 | 96×112 | 透明 |
| token | `mayor` / `medic` / `engineer` / `farmer` | 4 | **24×32** | 透明 |
| token | `recruit_workwear_a/b` / `recruit_utility_a/b` / `recruit_care_a/b` / `recruit_townsfolk_a/b` | 8 | 24×32 | 透明 |

- 施設スプライトの**接地フットプリントは 96×48 のダイアモンド**（2×1タイル相当）、フレーム下部中央に置く。建物はそこから上へ伸びる。**フットプリントはそのままヒット判定の基底**（docs/22 §6.1。実装は docs/23 §1.3 のレイアウトデータから生成し、スプライトと判定を分離しない）
- トークンの**接地スポットはフレーム下部中央の小さなダイアモンド**。身長はフレーム内で約26px
- 状態接尾辞は docs/22 §9.2 の基本セットから、**施設ごとの意味に合わせて確定**した（power は normal/low/working、road は collapsed/working/restored 等）
- **アニメーションのフレーム数は全点で1（静止画）**。状態変化はスプライト差し替え、動き（煙・雨・火花・浮遊表示）は Phaser の fx 層で描画する。トークンの負傷・探索中も画像差分を作らない（docs/22 §6.2: tint/バッジで表現）

### 1.3 町のレイアウト（ベースの構図の正・実装と共有）

ベース上の施設プロット配置（アイソメグリッド、奥=上）:

```text
            [山並み・松のシルエット]
        祠
   [発電]              [診療所]
[倉庫]      [本部]            ← 奥
        [広場]
              [崩落地点・町の出口] → 右端から外へ出る道
```

- **6プロットは建物のない空き地**として描く（建物は施設スプライトとして重ねる）
- 圧実土の小道が各プロットを繋ぐ。崩落地点の道は右端で土砂に遮られている
- 周囲に松・石垣・木柵。奥に低い山並みと祠を1つ
- この配置は実装側の `src/scene/town/layout.ts`（docs/22 §6.1）と同一の正であり、**画像とコードのどちらかが勝手に変えない**。変更は docs/22 の改訂を経る

### 1.4 トークンの割り当て方針（実装側・参考）

- トークンIDは**ユニットの portrait ID と同一**とする（`token/{portrait-id}.png` を解決）
- 初期4体（mayor/medic/engineer/farmer）は個別トークンを使用
- ユニーク30体は個別トークンを持たないため、肖像と同じ**決定的割り当て**（docs/14 §4 の流儀）で汎用8種へフォールバック。肖像とトークンが同テーマになるよう、割り当ては portrait ID → recruit プールへの固定写像とする
- 解決失敗時は Phaser 側のグリフ描画へフォールバック（docs/22 §9.2）

## 2. 生成プロンプト

docs/14 §3.1・docs/15 §2.1 と同じフィールド構成の英語プロンプトを使う。**共通部は固定し、`{ }` の差し替え変数のみ変更する**。

### 2.1 町ベース（`town/base`）

```text
Use case: stylized-concept
Asset type: 480x320 isometric town ground plate for a retro disaster-management game
Primary request: Create one isometric ground plate of a small isolated mountain village at night, in 2:1 diamond projection.
Scene/backdrop: Opaque flat dark navy sky (#0a0e24) at the top, a low mountain ridge and dark pine silhouettes along the back edge.
Subject: Bare village ground with packed-earth paths connecting six empty flat building plots on a diamond grid: headquarters plot at upper center, power shed plot at upper left, storehouse plot at left, gathering plaza at lower center, clinic plot at upper right, and a collapsed mountain road exiting at the lower right edge. A small shrine with a curved roof at the back, scattered pine trees, stone walls, wooden fences.
Style/medium: 16-bit pixel art, visible dithering, crisp hard pixel edges, no anti-aliasing.
Composition/framing: Isometric 2:1 diamond grid, village ground filling the lower two thirds, sky and mountains in the upper third, the six plots clearly readable as empty flat spaces.
Lighting/mood: Sparse cold night light from upper left, deep shadow to the lower right, quiet and tense.
Color palette: Use only #0a0e24 #131740 #1c2258 #e8ecff #ffc857 #ff5f66 #5ee6a8 #6fd8ff #ffd94a.
Constraints: Building plots must stay completely empty (buildings are separate sprites). Keep paths, plots, shrine, trees and mountains exactly reproducible, since facility sprites will be placed on top.
Avoid: text, letters, numbers, UI frame, watermark, buildings, people, animals, vehicles, modern architecture, neon, photorealism, smooth gradients, soft edges, transparent background.
```

### 2.4 制作手順

1. `scene/night.png`・既存イベント画像をパレット・ディザリング・光源の参照として確認する
2. `town/base` を単独で生成し、§1.3 の配置と一致することを確かめて**基準画像を固定する**
3. 実装トラックにベースへアイソメグリッドを重ねた**検図用オーバーレイ**（48×24タイルのガイド線PNG）を出力してもらう。以降のゲートで使用する
4. `hq-normal` を生成し、ベース上の所定プロットに重ねて**縮尺・接地・角度**を確認して施設の基準とする
5. 各施設の基準状態 → 状態差分の順に、**1アセット1生成コール**で制作する
6. トークンは `mayor` を基準に固定し、残り11点を同じスケール・姿勢・向きで制作する
7. 全施設+トークンをベースに並べ、同じ倍率で目視確認する（縮尺の揃い・浮き沈みのなさ）
8. 近傍法で完成サイズへ縮小し、固定パレットへ量子化する
9. 寸法・カラータイプ・色数・透過を機械確認し、採用品のみを配置する

**生成困難時の緩和策（アイソメ固有）**: `town/base` のプロット配置や施設の投影角度は、テキスト指定だけでは揃わないことが多い。以下を順に試す:

1. §1.3 のレイアウトを落書きした**テンプレート画像を入力にして生成**（img2img / 編集系機能。構図誘導）
2. 検図用オーバーレイ（手順3）を下絵として併用する
3. 生成後の**ピクセル単位の手直しを許可する**（プロットの位置合わせ・接地線の修正等）。手直し後も §3 のゲート（パレット・寸法・形式）を満たすこと

## 3. 画像ゲート

### 3.1 共通

- [ ] 完成サイズが §1.2 の表と一致する
- [ ] 使用色が指定9色の範囲内（量子化後）
- [ ] アンチエイリアスなし、indexed PNG
- [ ] 光源（左上）・影（右下）が `scene/night.png` と一致する
- [ ] テキスト・UI・未指定色・滑らかな勾配がない
- [ ] 既存のシーン・イベント画像と同じ作品世界に見える

### 3.2 投影・縮尺（アイソメ固有）

- [ ] ベースのプロット位置が §1.3 のレイアウトと一致する
- [ ] 全施設の接地フットプリントが 96×48 のダイアモンドに収まり、**検図用オーバーレイのタイル目と稜線の方向が揃う**
- [ ] ベースに重ねたとき浮き・沈み・角度の不整合がない（全施設・全トークン）
- [ ] 状態差分間で**建物の形状・接地・光源が変わっていない**（差分は状態要素のみ）
- [ ] トークンの身長・姿勢・向き・接地スポットが12点で揃っている

### 3.3 識別性

- [ ] 施設が実際表示サイズ（ベース上での縮小表示）で6種とも区別できる
- [ ] 状態（normal/low/working、collapsed/working/restored 等）がベース上で読み分けられる
- [ ] トークンが24×32で人物として認識でき、4初期キャラの区別がつく

## 4. 実装側での扱い（参考・別トラック）

- アセットは `src/assets/{kind}/{id}.png` に配置。ビルド時の URL マップ（`import.meta.glob`）経由で Phaser ローダーが読む（docs/22 §9.2）
- 既存の `icon/`（資源・任務・警報の各PNG）、`portrait/`、`ending/`、`event/`、`briefing/` も P3 で `src/assets/` へ移管され、HUD・詳細パネル・オーバーレイで再利用する。**`icon/procure` は PNG 未制作のまま移管されるため、Phaser 側でもグリフフォールバックが必要**
- manifest 相当（グリフ・色・ラベル）は `src/scene/art/` に再構築され、未着アセットはグリフ描画へフォールバック
- 施設表示は `deriveFacilityView(state, plan)` が状態ID（`power-low` 等）を選び、スプライトを差し替える（docs/22 §5.2・§6）
- トークン解決は `portrait ID → token/{id}.png → 汎用プール（決定的割り当て）→ グリフ` の順（§1.4）
