# 町・施設アート仕様

Issue #27「グラフィック最終品質向上」のワールドアート制作における**単一の正**を定める。

本ドキュメントは旧「Phase 4 最小セット」の制作計画を置き換える。町・施設・トークンについて、過去仕様との互換を目的とした別ルールや旧パレットを併存させない。以降のグラフィックPRはこの契約へ揃える。

---

## 1. 目標

画面を「ピクセルUIの上に町の配置図がある状態」から、**描かれた町そのものを操作している状態**へ移行する。

描き込みはワールド側へ集中し、HUD・ボタン・ゲージ・選択状態・通知などのUIはPhaser描画を維持する。

- **静止画**: 町、施設、恒常状態
- **Phaser FX**: 雨、煙、火花、点滅、危険パルスなど時間変化

アニメーション画像やUI装飾画像を増やして解決しない。

---

## 2. マスターリファレンス

Phase 0では次の2点を、後続制作の**幾何・縮尺・接地・カメラのマスター**として固定する。

- `src/assets/town/base.png`
- `src/assets/facility/hq-normal.png`

Phase 1で完成アートへ差し替える場合も、以下の幾何契約は変更しない。

- `town/base`: 480×320
- `facility/*`: 96×112
- 施設接地フットプリント: 96×48
- 2:1ダイアモンド投影
- 施設の接地点: フレーム下部中央
- `src/scene/town/layout.ts` のプロット座標
- 施設画像の不透明部分 + 接地フットプリントによる入力領域

つまりPhase 0のマスターは「現行絵を完成品質として保存する」という意味ではなく、**完成アートが必ず守る画面上の物理契約**である。

## 3. 投影・描画契約

| 項目 | 契約 |
| --- | --- |
| 投影 | 斜め見下ろし 2:1 ダイアモンド |
| 基準タイル | 48×24 px |
| 光源 | 左上 |
| 深い影 | 右下 |
| 画風 | 限定色の高密度16-bit系ピクセルアート |
| エッジ | ハードピクセル。アンチエイリアスなし |
| 勾配 | 滑らかなグラデーションは禁止。必要ならディザリング |
| 文字 | 画像内へ文字・数字・UIラベルを描かない |
| リサイズ | 完成サイズへの縮小は最近傍法 |
| アルファ | 0 / 255のみ。半透明ピクセルを作らない |

### 3.1 完成サイズ

| kind | 対象 | サイズ | 背景 |
| --- | --- | --- | --- |
| town | `base` | 480×320 | 不透明 |
| facility | 全施設 | 96×112 | 透明 |
| token | 全トークン | 24×32 | 透明 |

施設は96×48の接地フットプリント上に立つ。建物本体はそこから上方向へ伸ばし、状態差分間で建物形状・カメラ・接地点を変えない。

## 4. 色設計

### 4.1 UI色とワールド色を分離する

UIの意味色は既存テーマの責務とする。ワールドアートはUI状態色をそのまま全面配色として使わない。

従来のワールドアート9色制約は廃止し、**28色の固定パレット**へ置き換える。上限は32色とし、個別アセットが全色を使う必要はない。

## 5. 町ベース契約

`town/base` は単なる地面ではなく、**操作不能な環境情報で世界を説明する背景**とする。

描画候補:

- 石垣、木柵、土嚢
- 電柱、電線
- 豪雨後の泥、水たまり、側溝
- 畑、資材置場、ブルーシート
- 倒木、山肌、林
- 遠景家屋、祠
- 土砂、崩落の痕跡

ただし、6施設のプロットは建物のない空き地として保持する。背景装飾が施設スプライトの可読性や入力対象を誤認させてはいけない。

### プロット構成

```text
            [山並み・林]
        祠
   [発電]              [診療所]
[倉庫]      [本部]
        [広場]
              [崩落地点・町の出口] →
```

配置の正は `src/scene/town/layout.ts` とする。背景画像側だけで座標を変更しない。

## 6. 施設契約

施設を「アイコン」ではなく、その町に存在する建物・場所として描く。

### HQ master

`facility/hq-normal` は施設群の基準。後続施設は次を継承する。

- 同じ2:1投影
- 同じピクセル密度
- 同じ左上光源
- 同じ夜の色温度
- 同じ接地フットプリント
- 同程度のディテール密度
- 背景から識別できるが、HUDより高輝度にしない

想定モチーフ:

- 古い役場 / 公民館を転用した災害対策本部
- 木造または山村に馴染む構造
- 無線アンテナ
- 掲示板
- 数少ない窓明かり
- 臨時資材

### 状態差分

`normal / low / working / collapsed / restored` などは**同一物体の状態変化**として制作する。

変更してよいもの:

- 点灯 / 消灯
- 故障箇所
- 作業資材
- 散乱物
- 修復状況

変更してはいけないもの:

- カメラ角度
- 建物の主要形状
- 接地点
- フットプリント
- 基本縮尺
- 光源方向

煙・火花・雨など一時的な動きは画像へ焼き込まずPhaser FXへ残す。

## 7. AI生成・制作ルール

制作は**prompt-drivenではなくreference-driven**で行う。

1. `town/base` の幾何契約を参照する
2. `hq-normal` を施設の縮尺・接地・密度の参照にする
3. 施設normalを先に確定する
4. 状態差分は確定したnormalを参照して制作する
5. 完成サイズへ最近傍法で縮小する
6. World paletteへ量子化する
7. アルファを0/255へ正規化する
8. `npm run art:validate` を通す
9. 実画面wide/narrowで確認する
10. Visual Regression差分を確認する

### 共通生成指示

```text
Use case: production game asset
Game: a serious disaster-management simulation set in an isolated Japanese mountain village
Style: dense 16-bit pixel art, limited palette, hard pixel edges, visible controlled dithering, no anti-aliasing
Projection: strict 2:1 isometric diamond projection
Lighting: sparse cold night light from upper left, deep shadow to lower right, restrained warm practical lights
World: wet rural mountain village after heavy rain; old timber, stone, mud, emergency repairs and scarce electricity
Consistency: match the provided town/base and hq-normal references in camera, pixel density, lighting, material rendering and saturation
Avoid: text, letters, numbers, UI frames, badges, logos, watermark, photorealism, smooth gradients, soft edges, neon, modern urban architecture
```

施設スプライトでは追加で以下を固定する。

```text
Canvas: 96x112
Background: fully transparent
Footprint: invisible 96x48 2:1 diamond centered at the bottom of the frame
Keep the structure fully inside the frame and make it sit naturally on the reference town ground plate.
```

## 8. 機械ゲート

町アセット契約は `scripts/validate-town-art.mjs` で検証する。

`npm test` の先頭でも実行されるため、CIで自動的にゲートされる。

検証項目:

- 必須25アセットが過不足なく存在する
- town / facility / token の完成寸法
- `town/base` が不透明
- facility / token が透明背景を持つ
- 半透明ピクセルがない
- 不透明ピクセルがWorld palette内のみ
- 1アセットあたりの不透明色数が32色以下

これらを満たすための旧形式フォールバックや二重パレットは実装しない。不適合アセットは制作側で修正する。
